Storage · Snapshots & Versioning

Recover deleted and overwritten objects

Two independent, per-bucket, opt-in features. Every surface is designed backwards from the one question the PRFAQ flags as the biggest risk: “when is my object truly gone, and when do I stop paying for it?”

1 · Enable versioning & snapshots

per bucket

A new “Data protection” section in the create/edit bucket modal. Switch-gated, with lifecycle policies revealed on toggle.

2 · Object versions

in explorer

Version history lives in the preview pane. Restore, download, or delete any version — with snapshot-pin protection.

3 · Snapshots

bucket-wide

A new nav section. Take, browse, and restore point-in-time snapshots with a pre-restore diff.

4 · Snapshot ↔ DB backup

aligned

“Also restore storage” checkbox in the database restore flow — DB and objects return to the same point in time.

5 · Usage breakdown

cost clarity

Storage size splits into live / prior versions / snapshots, so a growing bill is always explainable.

6 · Trash

soft-deletes

Soft-deleted objects are out of the way but one click from restore, with an “auto-removes” honesty column.

ⓘ
Built against real Studio components — StorageMenuV2, EditBucketModal, PreviewPane, AttributeUsage, BackupsList. See README.md for the component-level spec and open questions.

CLI

CLI surface

For automation and CI. The version-ID scheme and command shape are a one-way door, so the surface is deliberately minimal and S3-compatible in spirit.

# Enable / configure (per bucket) $ supabase storage buckets update avatars --versioning enabled $ supabase storage buckets update avatars --snapshots enabled --snapshot-on-db-backup $ supabase storage buckets update avatars \ --version-expiry-days 30 --max-noncurrent-versions 10 --snapshot-expiry-days 90 ✓ Updated bucket "avatars" · versioning=enabled snapshots=enabled
# Object versions $ supabase storage versions list avatars/profile-jane.png VERSION SIZE CURRENT HELD BY SNAPSHOT MODIFIED 1a2b3c 412 KB yes — 2d ago 9f8e7d 398 KB no snap_...24_0300 6d ago 4c5d6e 405 KB no pre-migration 14d ago $ supabase storage versions restore avatars/profile-jane.png --version-id 9f8e7d ✓ Promoted 9f8e7d to current (new version 7a8b9c)
# Snapshots — restore prints the same diff the dashboard shows $ supabase storage snapshots restore snap_2026-07-20_0300 --dry-run Restoring snap_2026-07-20_0300 → bucket "avatars": + 14 objects added back ~ 3 objects reverted to earlier content - 22 objects created after the snapshot will be removed Re-run with --yes to apply. $ supabase storage trash list avatars $ supabase storage trash restore avatars/old-profile.png

Full command reference in README.md §8. Note: no versioning disabled — only suspended, matching the External FAQ one-way-door.

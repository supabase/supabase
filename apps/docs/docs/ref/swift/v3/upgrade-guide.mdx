v3 changes many public names and types, so expect compile errors when you upgrade. Most errors are a rename. This page covers the changes that affect every app. For the full list, including the changes that still compile but behave differently, read the [v3 migration guide](https://github.com/supabase/supabase-swift/blob/main/V3_MIGRATION.md) and the [module guides](https://github.com/supabase/supabase-swift/tree/main/docs/migrations/v3) for Auth, PostgREST, Storage, Functions, and Realtime.

## Upgrade the client library

<RefSubLayout.EducationRow>
  <RefSubLayout.Details>

    Install Xcode 26.0 or later (Swift 6.2 or later). Then update the package requirement. v3 also needs swift-crypto 4.0.0 or later. If your app pins swift-crypto below 4.0.0, raise the pin.

  </RefSubLayout.Details>
  <RefSubLayout.Examples>

    ```swift
    .package(url: "https://github.com/supabase/supabase-swift", from: "3.0.0-alpha.2")
    ```

  </RefSubLayout.Examples>
</RefSubLayout.EducationRow>

## Create the client with a configuration

<RefSubLayout.EducationRow>
  <RefSubLayout.Details>

    `SupabaseClientOptions` is now `SupabaseClient.Configuration`, and the initializer label is `configuration:`. The nested types drop their `Options` suffix, and `db` is now `database`.

    Every client initializer now throws when the URL has no scheme or no host. Add `try`.

    Headers are `HTTPFields`. Write each key as an `HTTPField.Name`.

  </RefSubLayout.Details>
  <RefSubLayout.Examples>

  <Tabs
    scrollable
    size="small"
    type="underlined"
    defaultActiveId="v2"
    queryGroup="version"
  >
    <TabPanel id="v2" label="Before">

      ```swift
      let client = SupabaseClient(
        supabaseURL: url,
        supabaseKey: key,
        options: SupabaseClientOptions(
          db: .init(schema: "app"),
          global: .init(headers: ["x-app": "demo"])
        )
      )
      ```

    </TabPanel>
    <TabPanel id="v3" label="After">

      ```swift
      var configuration = SupabaseClient.Configuration()
      configuration.database.schema = "app"
      configuration.global.headers = [HTTPField.Name("x-app")!: "demo"]

      let client = try SupabaseClient(
        supabaseURL: url,
        supabaseKey: key,
        configuration: configuration
      )
      ```

    </TabPanel>

  </Tabs>

  </RefSubLayout.Examples>
</RefSubLayout.EducationRow>

## Use swift-log for logging

<RefSubLayout.EducationRow>
  <RefSubLayout.Details>

    Every `logger:` parameter now takes a `Logging.Logger` from [swift-log](https://github.com/apple/swift-log). `SupabaseLogger` and `OSLogSupabaseLogger` are removed. Add swift-log to your package and `import Logging` where you build the logger.

    Debug builds now log warnings and errors to stderr when you pass no logger. Release builds stay silent.

  </RefSubLayout.Details>
  <RefSubLayout.Examples>

    ```swift
    import Logging
    import Supabase

    var logger = Logger(label: "myapp")
    logger.logLevel = .debug

    let client = try SupabaseClient(
      supabaseURL: url,
      supabaseKey: key,
      configuration: .init(global: .init(logger: logger))
    )
    ```

  </RefSubLayout.Examples>
</RefSubLayout.EducationRow>

## Replace `fetch` closures and `URLSession` options

<RefSubLayout.EducationRow>
  <RefSubLayout.Details>

    Every client sends requests through one `ClientTransport` behind an ordered list of `ClientMiddleware`. Both go in one `HTTPClientConfiguration`, passed as `http:`. `URLSessionTransport(session:)` wraps the `URLSession` that you used in v2.

    The SDK now sets the request timeout itself: 60 seconds, or 150 seconds for Functions. To change it, set `HTTPClientConfiguration(timeout:)`.

  </RefSubLayout.Details>
  <RefSubLayout.Examples>

  <Tabs
    scrollable
    size="small"
    type="underlined"
    defaultActiveId="v2"
    queryGroup="version"
  >
    <TabPanel id="v2" label="Before">

      ```swift
      let client = SupabaseClient(
        supabaseURL: url,
        supabaseKey: key,
        options: .init(global: .init(session: mySession))
      )
      ```

    </TabPanel>
    <TabPanel id="v3" label="After">

      ```swift
      let client = try SupabaseClient(
        supabaseURL: url,
        supabaseKey: key,
        configuration: .init(
          global: .init(http: .init(transport: URLSessionTransport(session: mySession)))
        )
      )
      ```

    </TabPanel>

  </Tabs>

  </RefSubLayout.Examples>
</RefSubLayout.EducationRow>

## Handle errors by module

<RefSubLayout.EducationRow>
  <RefSubLayout.Details>

    `HTTPError` is removed. Each module throws its own error (`AuthError`, `PostgrestError`, `StorageError`, `FunctionsError`, or `RealtimeError`). Each one conforms to `SupabaseError` and has a `kind`, a `code`, the `response`, and an `underlyingError`.

    A `URLError` or `DecodingError` no longer reaches you as itself. It arrives as the module error, with the original in `underlyingError`. A cancelled task now throws `CancellationError` in every module.

  </RefSubLayout.Details>
  <RefSubLayout.Examples>

    ```swift
    do {
      try await supabase.from("todos").insert(todo).execute()
    } catch PostgrestError.Code.uniqueViolation {
      showDuplicate()
    } catch PostgrestError.Kind.transport {
      showOfflineBanner()
    } catch let error as any SupabaseError {
      if let response = error.response {
        print(response.status.code, String(decoding: response.body, as: UTF8.self))
      }
    }
    ```

  </RefSubLayout.Examples>
</RefSubLayout.EducationRow>

## Other renames

<RefSubLayout.EducationRow>
  <RefSubLayout.Details>

    - `AnyJSON` is now `JSONValue`. Numbers are one case, `.number(JSONNumber)`, which keeps every digit.
    - `supabase.database` is removed. Use `supabase.from(_:)`, `supabase.rpc(_:)`, and `supabase.schema(_:)`.
    - `supabase.realtimeV2` is now `supabase.realtime`, and `supabase.channel(_:)` is `async`.
    - `supabase.handle(_:)` is now `supabase.handleRedirect(_:)`.
    - Methods that only read a value drop their `get` prefix. For example, `getPublicURL` is `publicURL`.
    - Arguments that name an identifier are `id:`, and acronyms keep their capitals, as in `factorID`.
    - Every API that was deprecated in v2.55.4 is removed.

  </RefSubLayout.Details>
</RefSubLayout.EducationRow>

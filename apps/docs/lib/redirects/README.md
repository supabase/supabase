# Docs redirects

Redirects for `/docs` URLs live here. Before this folder existed, most of them were in `apps/www/lib/redirects.js`, because `www` serves the docs zone through a rewrite.

Both files use full public paths, including the `/docs` prefix (for example `/docs/guides/...`).

| File                                          | Contains                                                                                                                | Served by                                                                     |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `static-redirects.json`                       | One-to-one mappings: a fixed `source` maps to a fixed `destination`, with no params, splats, regex, or `has`/`missing`. | Source only. Hand-edited.                                                     |
| `generated/static-redirects-md-variants.json` | Build output: `static-redirects.json` plus the generated `.md` variants. Gitignored.                                    | Vercel bulk redirects, through `bulkRedirectsPath` in `apps/docs/vercel.json` |
| `dynamic-redirects.js`                        | Anything with conditional logic: `:param`, `*` / `:path*` splats, regex groups, `has`, or `missing`.                    | Next.js `redirects()` in `apps/docs/next.config.mjs`                          |

Dev and preview only redirects (`/`, `/dashboard/*`, `/blog/*`) are in a separate section at the end of `dynamic-redirects.js`.

## Adding a redirect

1. If it has no params, splats, regex, or conditions, add it to `static-redirects.json`. Otherwise add it to `dynamic-redirects.js`.
2. In `static-redirects.json`, use the same shape as the existing entries:

   ```json
   { "source": "/docs/guides/old-path", "destination": "/docs/guides/new-path", "permanent": true }
   ```

   Do not add a `.md` entry by hand. The generator creates it for every `/docs/guides/` entry.

3. To preview the Vercel file locally, run:

   ```bash
   pnpm run redirects:generate
   ```

   The build (`redirects:generate` is a turbo dependency of `build`) regenerates it on every deploy, so do not commit it.

4. In `dynamic-redirects.js`, include `basePath: false`, because the sources are full public paths and Next must not add `/docs` again. `.md` variants for `/docs/guides/` entries are generated in `next.config.mjs`, so do not add them here:

   ```js
   {
     basePath: false,
     permanent: true,
     source: '/docs/guides/old-path/:slug',
     destination: '/docs/guides/new-path/:slug',
   },
   ```

5. Use `permanent: true` for permanent (308) redirects and `permanent: false` for temporary (307) redirects.
6. JSON does not support comments, so put the reason for a static entry in the PR description.
7. Keep each source unique within its file.
8. Run `pnpm test` in `apps/docs` to confirm that `next.config.mjs` still loads.

## Generator

`scripts/generate-static-redirects-md-variants.mjs` builds `generated/static-redirects-md-variants.json` from `static-redirects.json`:

- It adds a `.md` variant for every `/docs/guides/` entry with a string destination.
- It fails if a hand-written `.md` entry conflicts with a generated variant, or if a source is duplicated.
- It groups each base entry with its `.md` variant, base first, and sorts the groups by base path.

The generator runs as a turbo dependency of `build`, so an invalid source fails the build before anything deploys. The output is gitignored, so generated redirects do not appear in PR diffs. Run `pnpm run redirects:generate` to review them.

## Notes

- Bulk redirects ignore Next's `basePath`, which is why the JSON uses the `/docs` prefix.
- `.md` variants for dynamic `/docs/guides/` entries are generated at runtime in `next.config.mjs`. Static variants are generated by the script into `generated/static-redirects-md-variants.json`.
- `apps/www` runs its own redirects before it rewrites `/docs` to this app. Where the same source exists in both places, the `www` rule wins. `/docs/guides/database/inspect` is one case: `www` sends it to `/docs/guides/observability/inspect`, and the docs config used to send it to `/docs/guides/monitoring-and-debugging/inspect`. This folder keeps the `www` destination.

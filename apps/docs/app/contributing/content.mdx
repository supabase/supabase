# Contributing to Supabase Docs

Thank you for helping to improve the Supabase docs! The docs are open source, and we welcome your contributions. Every fix counts, from a one-word typo to a new guide.

The code and content for the docs are in the [Supabase GitHub repository](https://github.com/supabase/supabase), under the `apps/docs` directory.

## Be the change you want to see

If you see a typo, a broken link, or a step that is out of date, fix it and open a pull request. You do not need to ask first.

If you are not sure that something is wrong, open an [issue](https://github.com/supabase/supabase/issues/new/choose) and we will take a look.

If this is your first contribution, choose one of the [recommended issues](https://github.com/supabase/supabase/issues?q=is%3Aopen+is%3Aissue+label%3Adocumentation+label%3A%22help+wanted%22).

## Self-serve by default

We help you ship your docs. We are not gatekeepers. Three steps take your change from idea to published page:

1. Start with an issue. Describe what you want to add or fix, and who the page is for.
2. Use the [docs agent skills](https://github.com/supabase/supabase/blob/master/apps/docs/CONTRIBUTING.md#ai-agent-skills-for-docs-authoring). If you are new to the docs, start with `/write-the-docs`.
3. Open a pull request, and request a review from the docs team.

## Who to ask

The docs engineers own the docs site, the build, the tooling, the rendering, and the pull request review. Ask them in your pull request or issue.

The docs product manager owns the docs strategy. Ask in your issue when any of the following applies:

- The product stage or the audience is not clear.
- Your change affects pages that cover more than one product.
- You do not know who should review your change.

## Docs from outside the monorepo

Some docs live in other repositories. Use the style guide and the agent skills in your own repository, so that your docs meet the same bar as the rest of the docs.

If you cannot meet the bar, we can still link to your docs. Federated docs that keep breaking the docs build can be removed.

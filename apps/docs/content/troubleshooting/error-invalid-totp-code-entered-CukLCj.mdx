## Symptoms

TOTP verification returns `Invalid TOTP code entered` even though the user enters a six-digit value from an authenticator app.

## Confirm the cause

Confirm that the application submits the code for the intended enrolled factor and that the code has not rolled over before verification. Compare the authenticator device clock with an accurate time source; TOTP codes depend on the current time window, not the displayed time zone alone.

## Resolve

Enable automatic date and time synchronization on the authenticator device, then wait for a new code. Make sure the factor ID belongs to the current user and enrollment. If the device or factor was lost, use a separately enrolled recovery factor or follow the account recovery process rather than repeatedly retrying codes.

## Verify

Verify a newly generated code once and confirm that the Auth request succeeds. Avoid repeated retries with the same code because rate limits can obscure the original cause.

## Escalate

If new codes from a synchronized device fail for the confirmed factor, open a [support ticket](/dashboard/support/new) with the project reference, timestamp, SDK version, factor type, and sanitized Auth log error. Do not include the TOTP secret or one-time codes.

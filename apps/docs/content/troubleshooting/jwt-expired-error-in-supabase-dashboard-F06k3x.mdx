## Symptoms

The Dashboard repeatedly reports `JWT expired`, including immediately after a fresh sign-in or page reload.

## Confirm the cause

Sign out and sign in again. If a newly issued session is immediately considered expired, compare the computer clock with a trusted time source such as [time.is](https://time.is/). A large clock difference confirms local time drift.

## Resolve

Enable automatic date and time synchronization in the operating system, correct the clock, then sign in again. If the clock is already accurate, clear only the Supabase Dashboard session data or test a fresh browser profile before assuming the token itself is malformed.

## Verify

Reload the Dashboard and perform the action that previously failed. Confirm that the new session remains valid across another reload.

## Escalate

If the clock is synchronized and a fresh browser profile still rejects a newly issued Dashboard token, open a [support ticket](/dashboard/support/new) with the timestamp, browser and operating-system versions, and sanitized error. Do not include the JWT or cookies.

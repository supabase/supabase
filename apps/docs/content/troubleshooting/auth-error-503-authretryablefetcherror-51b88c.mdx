## Symptoms

Auth requests return HTTP `503` with `AuthRetryableFetchError`, often across multiple sign-in and user operations.

## Confirm the cause

Inspect the [Auth logs](/dashboard/project/_/logs/auth-logs). If service startup reports an invalid session timebox duration, the value corresponding to `GOTRUE_SESSIONS_TIMEBOX` cannot be parsed or exceeds the supported range. Common causes are:

- Exceeds the maximum supported duration (approximately hundreds of years).
- Uses an incorrect or unsupported time unit format.

If the Auth logs show a different startup error, follow that evidence instead of changing the session timebox.

## Resolve

1. Navigate to the [Sessions](/dashboard/project/_/auth/sessions) settings in the dashboard.
2. Locate the **Timebox** duration field within the **User Sessions** section.
3. Replace the current value with a smaller, valid duration or fallback to the default value (`4320` hours).
4. Save your changes.

Updating this field triggers a configuration reload, which allows the Auth service to restart and resume normal operation.

## Verify

Repeat an Auth health check and the original user operation. Confirm that both succeed and that the Auth logs no longer contain the configuration parse or startup error.

## Escalate

Open a [support ticket](/dashboard/support/new) if the timebox is valid or reset to its default and the Auth service still cannot initialize. Include the project reference, timestamp, sanitized `503` response, and Auth startup log message.

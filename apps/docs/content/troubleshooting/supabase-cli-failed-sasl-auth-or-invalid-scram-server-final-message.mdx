## Symptoms

`supabase link`, `supabase db push`, or another remote database command returns `failed SASL auth` or `invalid SCRAM server-final-message received from server`.

## Confirm the cause

1. Confirm that the CLI is linked to the intended project with `supabase projects list` and `supabase status` for the local stack.
2. Retry the command and enter the current database password at the prompt. A Management API access token is not the database password.
3. If authentication repeatedly fails, check [Database Settings](/dashboard/project/_/database/settings) for a temporary network ban affecting your current IP.
4. If password-based authentication succeeds but passwordless pooler authentication fails, test a direct IPv6 connection with `supabase link --skip-pooler`.

## Resolve

- Reset the database password when you no longer know the current value, then relink the project.
- Remove a network ban only after confirming that the listed address is yours and correcting the failed credentials that caused it.
- For non-interactive environments, supply the database password as documented. Quote the value so the shell does not interpret special characters:

  ```bash
  SUPABASE_DB_PASSWORD='your-database-password' supabase db push
  ```

- If your network supports IPv6 and the pooler path is the confirmed cause, link through the direct database connection:

  ```bash
  supabase link --project-ref your-project-ref --skip-pooler
  supabase db push
  ```

## Verify

Repeat the original CLI command. Confirm that it authenticates to the intended project and that the expected migration or inspection completes. Recheck the network-ban list to ensure the corrected workflow is not generating new failed attempts.

## Escalate

If the current password works through one connection path but the CLI still reports SASL or SCRAM failures through another, rerun the command with `--debug --create-ticket` and open a [support ticket](/dashboard/support/new) with the ticket ID. Do not paste passwords, access tokens, or complete connection strings into logs or the ticket.

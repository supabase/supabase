## Symptoms

An Auth email is sent with the default content instead of the saved customized template.

## Confirm the cause

Trigger the email and check the [Auth logs](/dashboard/project/_/logs/auth-logs) for `templatemailer_template_body_parse_error`. Auth uses a valid fallback template when the customized template cannot be parsed.

For example:

```
"event": "templatemailer_template_body_parse_error",
"msg": "templatemailer: template type \"recovery\": template: https://api.supabase.com/platform/auth/PROJECT_ID/templates/recovery:2: function \"default\" not defined",
```

The error identifies the unsupported `default` function in this template:

```
{{ .Data.display_name | default: "test" }}
```

## Resolve

Use only the variables and Go template syntax documented in [Auth email templates](/docs/guides/auth/auth-email-templates#terminology). In this example, remove the unsupported function:

```
{{ .Data.display_name }}
```

## Verify

Save the corrected template, trigger the same Auth email, and confirm that it contains the customization. Check that the Auth logs no longer contain a template parse error.

## Escalate

If the saved template parses without an Auth log error but the fallback is still sent, open a [support ticket](/dashboard/support/new) with the project reference, template type, timestamp, and sanitized template excerpt. Remove personal data and secrets.

## Symptoms

New connections fail with `too many connections for database "postgres"`, even though the server might still have unused connection slots.

## Confirm the cause

Check the per-database connection limit:

```sql
select datconnlimit
from pg_database
where datname = 'postgres';
```

The default `datconnlimit` is `-1`, which means that Postgres does not apply a separate limit to this database. See [`pg_database`](https://www.postgresql.org/docs/current/catalog-pg-database.html).

## Resolve

Reset an unintended non-default limit:

```sql
alter database postgres connection limit -1;
```

Do not reset a limit that your organization intentionally uses to isolate a database. If `datconnlimit` is already `-1`, investigate overall server connection use instead.

## Verify

1. Run the inspection query again and confirm that `datconnlimit` is `-1`.
2. Open a new connection with the affected client.
3. Confirm that the Postgres logs do not contain a new per-database connection-limit error.

## Escalate

Open a [support ticket](/dashboard/support/new) if the error continues with `datconnlimit = -1`. Include the project reference, timestamp with time zone, connection mode, compute size, current connection count, and redacted error.

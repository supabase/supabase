## Problem

Your Lovable project has **Lovable Cloud** enabled, and you’re trying to connect directly to your Supabase project.

However, you don’t see the project listed on your [Supabase Dashboard](/dashboard), or you’re unable to access it through your Supabase account.

## Why this occurs

When you create a project connected to **Lovable Cloud**, the underlying Supabase instance is provisioned and managed entirely by **Lovable**.

These projects are not owned by your Supabase account, so they **don't appear on your Supabase Dashboard** or be accessible using your Supabase credentials.

## How to diagnose

You might be affected by this if:

- You recently created a project on Lovable and enabled the backend from the chat interface. By default, the Lovable platform uses **Lovable Cloud** for backend hosting.
- You see Supabase references in your project’s configuration but **can’t access the project** from your [Supabase Dashboard](/dashboard).
- The project ID or credentials used in your Lovable setup don’t match any project under your Supabase account.
- You previously had your own Supabase project connected, but enabled Lovable Cloud by mistake and lost access to your Supabase backend from Lovable.

## How to fix

There is **no one-click transfer** from Lovable Cloud to your own Supabase account. However, you can export your data, restore it into a project you own, and then remove Lovable Cloud:

1. **Export your data.** In Lovable, open the project panel (layers icon in the top bar) and go to **Cloud > Overview > Advanced settings**, then use **Export data** to download a copy of your database. Exports are limited to 5 GB, and you can request one export every 24 hours. Download any storage files you need separately.

   ![Export, Pause, and Remove options in Lovable Cloud Advanced settings](/docs/img/troubleshooting/cant-access-supabase-project-lovable-cloud-0.png)

2. **Create your own Supabase project and import your data.** Create a project from the [Supabase Dashboard](/dashboard) and restore the exported data into it. See [Import Lovable Cloud Data into Your Own Supabase Project](/docs/guides/troubleshooting/import-lovable-cloud-data-to-supabase) for detailed restore steps and post-restore fixes. Verify that your data, users, and policies are in place before continuing.

3. **Remove Lovable Cloud.** Once you have verified the import, go to **Cloud > Overview > Advanced settings** and use the **Remove Lovable Cloud** flow. Lovable asks you to confirm the warnings and type the project name before removal.

   ![Remove Lovable Cloud confirmation dialog](/docs/img/troubleshooting/cant-access-supabase-project-lovable-cloud-1.png)

4. **Connect your own Supabase project.** Connect the new project to your Lovable project by following Lovable's official guide: [Connect to Supabase (Lovable Docs)](https://docs.lovable.dev/integrations/supabase).

   ![Connect your own Supabase project after removing Lovable Cloud](/docs/img/troubleshooting/cant-access-supabase-project-lovable-cloud-2.png)

For more details, see Lovable's [Cloud documentation](https://docs.lovable.dev/integrations/cloud).

<Admonition type="note">

If you enabled Lovable Cloud by mistake and your data still lives in your own Supabase project, you can skip the export and import steps: remove Lovable Cloud and reconnect your Supabase project. If you added data while Lovable Cloud was enabled, that data lives in the Cloud instance, so export it before removing.

</Admonition>

<Admonition type="danger">

Removing Lovable Cloud permanently deletes the Cloud instance, including your database tables, users, storage, edge functions, and secrets. This cannot be undone. Export your database and download any storage files you need before removing Lovable Cloud.

</Admonition>

## How to prevent

If you want direct access to your Supabase project from the start, make sure to:

- Avoid enabling Lovable Cloud if you plan to manage your Supabase project independently.
- Create your project directly from the [Supabase Dashboard](/dashboard) and then **manually connect your Lovable project to your Supabase project**, or **start your Lovable project already connected** to your own Supabase project from the beginning.

  <AccordionItem
      header="Why doesn't my Supabase project appear on my dashboard?"
      id="project-not-showing"
    >

    Lovable Cloud projects are owned and managed by **Lovable**, not by your personal Supabase account. They won't show up on your dashboard.

    </AccordionItem>

  <AccordionItem
      header="Can I disconnect my project from Lovable Cloud and connect it to my own Supabase account?"
      id="disconnect-project"
    >

    Yes. You can remove Lovable Cloud from your project under **Cloud > Overview > Advanced settings > Remove Lovable Cloud**, then connect your own Supabase project through the [Supabase integration](https://docs.lovable.dev/integrations/supabase).

    Removing Lovable Cloud **permanently deletes** the Cloud instance and its data, so export your database first. There is no one-click transfer: you need to re-import your data and reconfigure authentication and external services manually.

    </AccordionItem>

  <AccordionItem
      header="Can I get access to the Supabase SQL editor when using Lovable Cloud?"
      id="sql-editor-access"
    >

    Projects running on **Lovable Cloud** use a managed Supabase backend that doesn't provide access to the SQL editor on [supabase.com/dashboard](/dashboard).

    However, Lovable Cloud includes its own SQL editor inside Lovable, under **Cloud > SQL editor**. You can also make schema and policy changes via SQL migrations, or ask the Lovable agent to run SQL for you.

    To use the Supabase SQL editor on the Supabase Dashboard, remove Lovable Cloud and connect your own Supabase project (see [How to fix](#how-to-fix)).

    </AccordionItem>

  <AccordionItem
      header="I can't get my database URL to connect from an external tool (like BI tools or Postgres connectors)."
      id="database-url"
    >

    Direct database connections are **not supported** when your project runs on Lovable Cloud.

    Many external services can connect to your app through [Lovable's connectors](https://docs.lovable.dev/integrations/introduction) instead, which offer 70+ pre-built integrations.

    If you need a direct Postgres connection (for example, for BI tools), remove Lovable Cloud and connect your own Supabase project (see [How to fix](#how-to-fix)).

    </AccordionItem>

  <AccordionItem
      header="I can't get my service role key to integrate an external service (like n8n or Make.com)."
      id="service-role-key"
    >

    Service role and API keys are **not accessible** for Lovable Cloud–managed projects.

    To integrate with external automation or API-based tools, remove Lovable Cloud and connect your own Supabase project (see [How to fix](#how-to-fix)).

    </AccordionItem>

</Accordion>

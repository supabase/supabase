## Symptoms

The CLI returns HTTP `403` with `Forbidden resource` while linking a project or performing a protected project operation.

## Confirm the cause

1. Confirm the project reference in the command. Find the reference under [Project Settings > General](/dashboard/project/_/settings/general).
2. Run `supabase projects list` and confirm that the authenticated account can see the project.
3. Check that your organization role grants the permission required by the command. See [access control](/docs/guides/platform/access-control).
4. If the token was revoked or belongs to another account, create an [access token](/dashboard/account/tokens), run [`supabase login`](/docs/reference/cli/supabase-login), and relink the project.

## Resolve

Use the correct project reference and an access token owned by an account with the required project permission. Update the CLI if the same authorized request works in the Dashboard but fails only on an older CLI release.

## Verify

Run `supabase projects list`, relink the intended project, and repeat the original operation. Confirm that the CLI operates on the expected project before applying migrations or other changes.

## Escalate

If the authorized account can perform the operation in the Dashboard but the CLI still returns `403`, rerun the command with `--debug --create-ticket` and open a [support ticket](/dashboard/support/new) with the ticket ID and CLI version. Do not include access tokens, database passwords, or complete connection strings.

## Symptoms

A request to a configured custom domain returns Cloudflare `1016 Origin DNS error`, while the project's default `*.supabase.co` URL might still work.

## Confirm the cause

Check the [custom domain settings](/dashboard/project/_/settings/custom-domain) and your DNS provider. Confirm that the verification records exactly match the values shown in the Dashboard and that no proxy, flattening, or stale record changes the expected result.

## Resolve

1.  Navigate to your project's [custom domain settings](/dashboard/project/_/settings/custom-domain).
2.  Initiate a DNS record re-verification. This action prompts an attempt to renew the SSL certificate.
3.  If the error persists after re-verification, remove the custom domain configuration from your project.
4.  Re-add the custom domain configuration. Ensure all DNS records are correctly established as instructed by the dashboard. This process forces a hard reset and triggers a new certificate request.

Removing and re-adding the domain causes an interruption. Use it only after verifying the DNS records and allowing time for DNS changes to propagate.

## Verify

Resolve the hostname from more than one network and request the custom domain over HTTPS. Confirm that it reaches the intended Supabase service and presents a certificate valid for the hostname.

## Escalate

Open a [support ticket](/dashboard/support/new) if the Dashboard shows the domain as verified, public DNS returns the expected records, and requests still return `1016`. Include the project reference, hostname, timestamp, DNS responses, and custom-domain status. Do not include private keys or API credentials.

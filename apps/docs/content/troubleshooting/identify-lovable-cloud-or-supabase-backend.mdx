## Overview

When you create a project in **Lovable**, your app’s backend can be connected to one of two options:

- **Lovable Cloud** — The backend (Supabase instance) is managed entirely by **Lovable**.
- **Your own Supabase project** — The backend is a Supabase project you created and manage directly in your [Supabase Dashboard](/dashboard).

Knowing which backend your project uses helps you understand where your database, API keys, and configuration are managed.

## How to identify your backend

In the Lovable editor, click the **layers icon** on the top bar of your project. This opens the project panel, where the left sidebar shows which backend your project is currently connected to.

![Layers icon that opens the project panel in Lovable](/docs/img/troubleshooting/identify-lovable-cloud-or-supabase-backend-0.png)

<Admonition type="note">

The panel appears for all projects, regardless of which backend type you're using. Open it to see your actual backend configuration.

</Admonition>

Once the panel is open, you see one of these states depending on your backend type:

### Lovable Cloud backend

If the **Cloud** section in the sidebar expands into managed sections such as **Database**, **Users**, **Storage**, **Secrets**, **Edge functions**, and **SQL editor** (similar to the screenshot below), then your backend is managed by **Lovable Cloud**.

![Lovable Cloud backend sections inside Lovable](/docs/img/troubleshooting/identify-lovable-cloud-or-supabase-backend-1.png)

Your Supabase instance in this case is **owned and managed by Lovable**, not by your personal Supabase account.
You won’t see this project in your Supabase Dashboard, and you won’t have access to service role keys or direct database URLs.

### Connected Supabase backend

If the panel displays a **Supabase** card marked **Connected**, with your Supabase project name and links that open the Supabase Dashboard (Manage users, SQL editor, Edge functions, Manage secrets), then your Lovable project is connected to a **Supabase project you manage directly**.

![Supabase connected card inside Lovable](/docs/img/troubleshooting/identify-lovable-cloud-or-supabase-backend-2.png)

### No backend enabled

If the **Cloud > Overview** section shows an **Enable more features** prompt instead of managed sections, your project has no backend yet. From here you can enable Lovable Cloud, or connect a Supabase project you own through the **"Already have a Supabase project? Connect it here"** link.

![Project with no backend enabled yet](/docs/img/troubleshooting/identify-lovable-cloud-or-supabase-backend-3.png)

## Summary

| Backend Type             | Managed By | Appears in Supabase Dashboard | Service Role / DB Access |
| ------------------------ | ---------- | ----------------------------- | ------------------------ |
| **Lovable Cloud**        | Lovable    | ❌ No                         | ❌ No                    |
| **Own Supabase Project** | You        | ✅ Yes                        | ✅ Yes                   |

## Frequently asked questions

<Accordion
  type="default"
  chevronAlign="right"
  justified
  size="medium"
  className="text-foreground-light mt-8 mb-6"
>
  <AccordionItem
      header="Does this affect where my app is hosted?"
      id="app-hosting"
    >

    No. Lovable Cloud only affects your **backend connection** (database and APIs), not your app hosting or frontend.

    </AccordionItem>

  <AccordionItem
      header="Can I access my database URL or API keys if I'm on Lovable Cloud?"
      id="database-api-access"
    >

    Not for direct access. The service role key and direct database URLs are not exposed for Lovable Cloud–managed projects, and the project can't be opened from the Supabase Dashboard.

    Your app's project URL and publishable (anon) key do exist in your project's code, but they only serve your app's client-side requests. If you need full credential access (service role key, direct Postgres connections for BI or automation tools), migrate to your own Supabase project — see [Import Lovable Cloud Data into Your Own Supabase Project](/docs/guides/troubleshooting/import-lovable-cloud-data-to-supabase).

    </AccordionItem>

  <AccordionItem
      header="Can I switch from Lovable Cloud to my own Supabase backend?"
      id="switch-backend"
    >

    Yes. Export your data from **Cloud > Overview > Advanced settings**, create a new Supabase project, restore and verify the import, then remove Lovable Cloud and connect the new project.

    See [Can't Access Supabase Project When Using Lovable Cloud](/docs/guides/troubleshooting/cant-access-supabase-project-lovable-cloud) for the full flow, and [Import Lovable Cloud Data into Your Own Supabase Project](/docs/guides/troubleshooting/import-lovable-cloud-data-to-supabase) for the restore steps.

    </AccordionItem>

</Accordion>

## Lovable Cloud – specific questions

<Accordion
  type="default"
  chevronAlign="right"
  justified
  size="medium"
  className="text-foreground-light mt-8 mb-6"
>
  <AccordionItem
      header="My project uses Lovable Cloud, can I move it to Supabase?"
      id="move-to-supabase"
    >

    Yes. Lovable Cloud provides a native data export that includes your full schema, data, RLS policies, and auth users with their password hashes. Export your data, create a new Supabase project, restore and verify the import, then remove Lovable Cloud and connect the new project.

    See [Can't Access Supabase Project When Using Lovable Cloud](/docs/guides/troubleshooting/cant-access-supabase-project-lovable-cloud) for the full flow, and [Import Lovable Cloud Data into Your Own Supabase Project](/docs/guides/troubleshooting/import-lovable-cloud-data-to-supabase) for the restore steps.

    </AccordionItem>

  <AccordionItem
      header="My project uses Lovable Cloud, but I can't see my Supabase project."
      id="cant-see-project"
    >

    That's expected — Lovable Cloud backend is managed by Lovable and doesn't appear in your Supabase Dashboard.

    Learn more in [Can't Access Supabase Project When Using Lovable Cloud](/docs/guides/troubleshooting/cant-access-supabase-project-lovable-cloud).

    </AccordionItem>

</Accordion>

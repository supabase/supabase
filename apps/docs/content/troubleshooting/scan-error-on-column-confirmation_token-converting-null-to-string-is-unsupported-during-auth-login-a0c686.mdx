## Symptoms

An Auth login returns HTTP `500` with `error finding user: sql: Scan error on column "confirmation_token": converting NULL to string is unsupported`.

## Confirm the cause

Inspect the affected rows before changing them:

```sql
select id
from auth.users
where confirmation_token is null;
```

This state usually comes from a manual import or write to the service-managed `auth.users` table.

## Resolve

After backing up the affected rows, update only the exact column and rows identified by the error in the [SQL Editor](/dashboard/project/_/sql/new):

```sql
update auth.users set confirmation_token = '' where confirmation_token is null;
```

Stop any application, migration, or import process that writes `NULL` back to this column. Prefer supported Auth administration APIs over direct writes to `auth.users`.

## Verify

Repeat the login for an affected user and confirm that it succeeds. Check Auth and Postgres logs for the new time window and verify that the scan error no longer appears.

## Escalate

Open a [support ticket](/dashboard/support/new) if the rows were not created by a project-owned import or direct write, or if the exact scan error continues after the affected values are corrected. Include the project reference, timestamp, affected user IDs, and sanitized log messages; do not include tokens or passwords.

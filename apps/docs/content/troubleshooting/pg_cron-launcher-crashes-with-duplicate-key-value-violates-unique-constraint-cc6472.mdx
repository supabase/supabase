The `pg_cron` launcher process crashes approximately every minute, displaying the error `'duplicate key value violates unique constraint "job_run_details_pkey"'`.

## Why does this happen?

This issue occurs when the `cron.runid_seq` sequence is out of sync with the `cron.job_run_details` table. The sequence attempts to generate `runid` values that already exist in the table, leading to a unique key violation. This is typically due to the sequence's last value not being correctly aligned with the maximum `runid` already present in the table.

## Confirm the cause

Compare the sequence with the greatest stored run ID:

```sql
select
  (select last_value from cron.runid_seq) as sequence_value,
  (select max(runid) from cron.job_run_details) as maximum_run_id;
```

The sequence is behind when `sequence_value` is less than or equal to `maximum_run_id`.

## Resolve

Advance the sequence without deleting job history. Run this in the [SQL Editor](/dashboard/project/_/sql/new):

```sql
select
  setval('cron.runid_seq', coalesce((select max(runid) from cron.job_run_details), 0) + 1, false);
```

Do not truncate `cron.job_run_details` solely to repair the sequence; truncation permanently deletes the execution history used for diagnosis.

## Verify

Wait for the next scheduled run and confirm that it inserts a new row with a run ID above the previous maximum. Check the Postgres logs and verify that the duplicate-key error does not recur.

## Escalate

Open a [support ticket](/dashboard/support/new) if the sequence falls behind again without a restore, manual write, or migration that explains the change. Include the project reference, extension version, timestamps, sequence values, and sanitized Postgres log error.

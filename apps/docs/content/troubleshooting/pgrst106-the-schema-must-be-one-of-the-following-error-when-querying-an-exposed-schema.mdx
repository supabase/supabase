## Symptoms

The Data API returns `PGRST106` and lists schemas that do not include the custom schema selected by the request, even though the schema appears in the Dashboard configuration.

## Confirm the cause

1. Confirm that the schema is listed under [Project Settings > Data API](/dashboard/project/_/integrations/data_api/settings).
2. Inspect the role-level override:

   ```sql
   select rolconfig
   from pg_roles
   where rolname = 'authenticator';
   ```

3. If `rolconfig` contains `pgrst.db_schemas=...`, that database setting overrides the Dashboard-managed value.

## Resolve

Reset the manual override so the Dashboard configuration can take effect:

```sql
alter role authenticator reset pgrst.db_schemas;
notify pgrst, 'reload config';
```

Then save the intended exposed schemas in [Data API settings](/dashboard/project/_/integrations/data_api/settings). Grant only the schema and object privileges required by the request, and enable RLS on tables exposed through the API.

## Verify

Repeat the request with the same `Accept-Profile` or `Content-Profile` schema selection. Confirm that it no longer returns `PGRST106`, then verify that a schema not configured for exposure remains inaccessible.

## Escalate

Open a [support ticket](/dashboard/support/new) if the role override is absent and the Data API continues to advertise a schema list that differs from the saved Dashboard configuration. Include the project reference, timestamp, requested schema, sanitized response, and `rolconfig` output.

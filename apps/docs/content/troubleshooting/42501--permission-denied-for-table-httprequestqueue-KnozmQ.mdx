## Symptoms

A database webhook or `pg_net` request fails with SQLSTATE `42501` and `permission denied for table http_request_queue`.

## Confirm the cause

1. Check the Postgres logs for the exact SQLSTATE, role, and timestamp.
2. Inspect the extension and queue without reading request payloads:

   ```sql
   select extversion, extnamespace::regnamespace as schema
   from pg_extension
   where extname = 'pg_net';

   select count(*) as queued_requests
   from net.http_request_queue;
   ```

3. Confirm that `pg_net` is installed and that the error comes from its worker or a webhook operation rather than from application SQL that reads the internal queue directly.

## Resolve

Install available database software updates from [Infrastructure Settings](/dashboard/project/_/settings/infrastructure), then restart the `pg_net` worker as described in the [webhook debugging guide](/docs/guides/troubleshooting/webhook-debugging-guide-M8sk47).

Do not drop and recreate `pg_net` as a first response. Dropping the extension can discard queued requests and fails when dependent objects exist.

## Verify

1. Send one test webhook or `pg_net` request.
2. Confirm that the request leaves `net.http_request_queue` and receives a response entry.
3. Confirm that the Postgres logs do not contain a new `42501` error for the operation.

## Escalate

Open a [support ticket](/dashboard/support/new) if the error remains after an available software update and worker restart. Include the project reference, timestamp with time zone, `pg_net` version, queue count, database role, and redacted Postgres log entry.

Each Supabase project is provisioned on hardware in the chosen region, so it is bound to a region at the infrastructure level.

To change the region of a project, create a new project in the desired region and migrate your existing project using the [migrations guide](/docs/guides/platform/migrating-within-supabase/backup-restore).

If you use third-party auth providers such as Facebook or Google, manually copy your client ID and secret pairs to the new project in the Supabase Dashboard. Also update your API URL and [API keys](/docs/guides/getting-started/api-keys) (publishable, secret, `anon`, or `service_role` keys), usually through environment variables on your web host.

## Project configurations

You can copy the project configurations from one project to another using the [Management API](/docs/reference/api/introduction). The Management API lets you retrieve configurations from various services, such as Auth, Realtime, and Storage, and apply them to any project where you have Owner or Admin permissions.

To copy the configurations, run the script in [Copy project configurations](/docs/guides/troubleshooting/restore-project-after-90-days-pause#step-5-copy-project-configurations). It accepts an access token and the source and destination project references.

## Minimize downtime

For minimal downtime, use [logical replication](/docs/guides/platform/migrating-to-supabase/postgres#method-3-logical-replication).

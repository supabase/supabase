## Symptoms

`supabase.auth.getUser()` returns HTTP `401` or `403` with `invalid claim: missing sub`.

## Confirm the cause

Inspect how the client or server obtains the token passed to `getUser()`. The error is confirmed when the value is a publishable, anon, secret, or service-role API key, a malformed token, or an incomplete session rather than a user access token containing a `sub` claim.

## Resolve

- Complete sign-in before calling `getUser()`.
- In browser flows, let the Supabase client read the current Auth session rather than passing the project API key as a user token.
- On a server, create the client for each request and forward the user's session through the framework's supported cookie flow. If you explicitly pass a token, use the user's bearer access token: `Authorization: Bearer <user-access-token>`.
- Never expose a secret or service-role key in the browser.

## Verify

Repeat the request after a completed sign-in. Confirm that `getUser()` returns the expected user and that Auth logs no longer contain `missing sub`. Also confirm that an API key by itself cannot be treated as a user session.

## Escalate

If a freshly issued user access token still produces `missing sub`, include the SDK version, Auth operation, timestamp, and a decoded claim-name list in a [support ticket](/dashboard/support/new). Do not include the token value or user data.

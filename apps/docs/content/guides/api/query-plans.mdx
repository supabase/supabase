Find out why a Data API query is slow by reading its Postgres `EXPLAIN` execution plan. Chain `explain()` to any query, including `rpc()` calls and writes, to get the plan instead of the data.

`explain()` is disabled by default, because a plan reveals details of your database structure and operations. Enable it in a non-production environment. To use it in production, [restrict it to your own IP address](#production-use-with-pre-request-protection).

## Enabling `explain()`

Run the following SQL using the [SQL Editor](/dashboard/project/_/sql) in the Supabase Dashboard or with `psql` over a direct connection. To connect with `psql`, see [Direct connection](/docs/guides/database/connecting-to-postgres#direct-connection).

{/* prettier-ignore */}
```sql
alter role authenticator
set pgrst.db_plan_enabled to 'true';

notify pgrst, 'reload config';
```

## Using `explain()`

1. If you don't have a table to query, create an `instruments` table with sample data:

   {/* prettier-ignore */}
   ```sql
   create table instruments (
     id int8 primary key,
     name text
   );

   insert into instruments
     (id, name)
   values
     (1, 'violin'),
     (2, 'viola'),
     (3, 'cello');
   ```

2. Chain `explain()` to a query:

   {/* prettier-ignore */}
   ```ts
   const { data, error } = await supabase
     .from('instruments')
     .select()
     .explain()
   ```

   `data` holds the plan:

   {/* prettier-ignore */}
   ```markdown
   Aggregate  (cost=33.34..33.36 rows=1 width=112)
     ->  Limit  (cost=0.00..18.33 rows=1000 width=40)
           ->  Seq Scan on instruments  (cost=0.00..22.00 rows=1200 width=40)
   ```

The plan is in text format by default. To get it as JSON, pass the `format` parameter.

## Production use with pre-request protection

To use `explain()` in production, restrict it with a pre-request function. The function below rejects plan requests from every IP address except yours. Replace `'123.123.123.123'` with your IP address.

{/* prettier-ignore */}
```sql
create or replace function filter_plan_requests()
returns void as $$
declare
  headers   json := current_setting('request.headers', true)::json;
  client_ip text := coalesce(headers->>'cf-connecting-ip', '');
  accept    text := coalesce(headers->>'accept', '');
  your_ip   text := '123.123.123.123';
begin
  if accept like 'application/vnd.pgrst.plan%' and client_ip != your_ip then
    raise insufficient_privilege using
      message = 'Not allowed to use application/vnd.pgrst.plan';
  end if;
end; $$ language plpgsql;
alter role authenticator set pgrst.db_pre_request to 'filter_plan_requests';
notify pgrst, 'reload config';
```

## Disabling explain

When you're done, disable `explain()`. If you set up the pre-request function, the second statement removes it.

{/* prettier-ignore */}
```sql
alter role authenticator
set pgrst.db_plan_enabled to 'false';

alter role authenticator
set pgrst.db_pre_request to '';

notify pgrst, 'reload config';
```

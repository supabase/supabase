Match each Vercel preview deployment to its Supabase preview branch, so every preview runs against the right database schema, Edge Functions, and other Supabase configuration. For how branching works with other hosting providers, see [Branching integrations](/docs/guides/deployment/branching/integrations).

## Before you begin

- Set up [branching with GitHub](/docs/guides/deployment/branching/github-integration) on your Supabase project.
- Install the [Vercel GitHub integration](https://vercel.com/docs/deployments/git/vercel-for-github) on your Vercel project.

## Connect Vercel

1. Install the Supabase integration for Vercel in one of these ways:
   - From the [Vercel marketplace](https://vercel.com/integrations/supabase).
   - By clicking the blue **Deploy** button in a Supabase example app's `README` file.
2. In the [**Integrations**](/dashboard/org/_/integrations) section of your organization settings, connect your Supabase project to your Vercel project.

## How preview deployments get their variables

Supabase updates your Vercel project with the environment variables for each preview branch. It syncs them when a pull request opens, not when the branch is created.

The integration depends on Vercel preview deployments, so Vercel can start a deployment before Supabase sets the variables. To cover that, Supabase redeploys the most recent deployment of the pull request.

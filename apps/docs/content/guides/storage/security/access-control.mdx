Control who can upload, list, read, and overwrite files in Supabase Storage by writing Row Level Security (RLS) policies on the `storage.objects` table. When you finish, only the people and folders you allow can reach your files.

## Overview

Storage uses Postgres [Row Level Security](/docs/guides/database/postgres/row-level-security) policies on the `storage.objects` table. By default, Storage doesn't allow any uploads without a policy, so you allow each operation you need. To learn how Storage organizes buckets and objects, see the [storage schema](/docs/guides/storage/schema/design).

## Procedure

You will write a policy that lets each user upload to their own folder, then one that lets them read it back.

### 1. Allow uploads to a user's folder

Uploading needs an `INSERT` policy on `storage.objects`.

1. Open the [SQL Editor](/dashboard/project/_/sql/new).

2. Create a policy that lets authenticated users upload to a folder named with their user ID inside your bucket:

   ```sql
   create policy "Allow authenticated uploads"
   on storage.objects
   for insert
   to authenticated
   with check (
     bucket_id = 'my_bucket_id' and
     (storage.foldername(name))[1] = (select auth.jwt()->>'sub')
   );
   ```

### 2. Allow users to read their own files

Reading needs a separate `SELECT` policy.

1. In the SQL Editor, open a new query.

2. Create a policy that lets a user read the files they uploaded:

   ```sql
   create policy "Individual user Access"
   on storage.objects for select
   to authenticated
   using ( (select auth.jwt()->>'sub') = owner_id );
   ```

## Verify

Confirm the policies allow your own folder and reject someone else's.

1. Sign in as a user and upload a file to your own folder. The upload succeeds.

2. Sign in as a different user and upload a file to the first user's folder. The policy rejects the request.

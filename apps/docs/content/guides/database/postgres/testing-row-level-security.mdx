Prove each Row Level Security (RLS) policy allows and blocks what you meant by running [pgTAP](https://pgtap.org) tests against your local database. To learn how policies work, see [Row Level Security](/docs/guides/database/postgres/row-level-security).

## Write and run a policy test

The example tests a `todos` table whose policy lets each user access only their own rows.

1. Open a terminal in your project and start the local stack:

   ```bash
   supabase start
   ```

2. Create a migration for the table and its policy:

   ```bash
   supabase migration new create_todos
   ```

   In the new `supabase/migrations/<timestamp>_create_todos.sql` file, add the following SQL:

   ```sql
   create table todos (
     id uuid primary key default gen_random_uuid(),
     task text not null,
     user_id uuid references auth.users not null,
     completed boolean default false
   );

   alter table todos enable row level security;

   create policy "Users can only access their own todos"
   on todos for all
   to authenticated
   using ((select auth.uid()) = user_id);
   ```

   Apply the migration to your local database:

   ```bash
   supabase db reset
   ```

3. Create the test file:

   ```bash
   supabase test new todos_rls
   ```

4. In `supabase/tests/todos_rls_test.sql`, write the tests:

   ```sql supabase/tests/todos_rls_test.sql
   begin;
   create extension if not exists pgtap with schema extensions;
   select plan(4);

   insert into auth.users (id, email)
   values
     ('123e4567-e89b-12d3-a456-426614174000', 'user1@test.com'),
     ('987fcdeb-51a2-43d7-9012-345678901234', 'user2@test.com');

   insert into public.todos (task, user_id)
   values
     ('User 1 Task 1', '123e4567-e89b-12d3-a456-426614174000'),
     ('User 1 Task 2', '123e4567-e89b-12d3-a456-426614174000'),
     ('User 2 Task 1', '987fcdeb-51a2-43d7-9012-345678901234');

   -- as user 1
   set local role authenticated;
   set local request.jwt.claim.sub = '123e4567-e89b-12d3-a456-426614174000';

   select results_eq(
     'select count(*) from todos',
     array[2::bigint],
     'User 1 sees only their 2 todos'
   );

   -- returning proves the row was written, not only that nothing failed
   select results_eq(
     $$insert into todos (task, user_id)
       values ('New Task', '123e4567-e89b-12d3-a456-426614174000'::uuid)
       returning task$$,
     array['New Task'],
     'User 1 can create their own todo'
   );

   -- as user 2
   set local request.jwt.claim.sub = '987fcdeb-51a2-43d7-9012-345678901234';

   select results_eq(
     'select count(*) from todos',
     array[1::bigint],
     'User 2 sees only their 1 todo'
   );

   select is_empty(
     $$update todos set task = 'Hacked!'
       where user_id = '123e4567-e89b-12d3-a456-426614174000'::uuid
       returning 1$$,
     'User 2 cannot modify User 1 todos'
   );

   select * from finish();
   rollback;
   ```

   The file runs in one transaction that rolls back at the end, so the test data never persists. `set local role` and `request.jwt.claim.sub` set the role and user each assertion runs as, the way a signed-in user's request does.

5. Run the tests:

   ```bash
   supabase test db
   ```

   ```text
   psql:todos_rls_test.sql:2: NOTICE:  extension "pgtap" already exists, skipping
   ./todos_rls_test.sql .. ok
   All tests successful.
   Files=1, Tests=4,  0 wallclock secs ( 0.01 usr +  0.00 sys =  0.01 CPU)
   Result: PASS
   ```

The policy now has a test that fails if a change lets one user read or edit another user's todos.

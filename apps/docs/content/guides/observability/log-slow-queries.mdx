---

Find slow and failing queries by recording them in your Postgres logs. To read the logs, see [Logs in Studio](/docs/guides/observability/logs). For every log setting, see [Postgres log configurations](/docs/guides/database/postgres/postgres-log-config).

<Admonition type="caution">

Logging a large amount of query activity can slow your queries and increase logging costs. Lower a threshold while you investigate, and raise it again when you're done.

</Admonition>

Run the following SQL using the [SQL Editor](/dashboard/project/_/sql) in the Supabase Dashboard or with `psql` over a direct connection. To connect with `psql`, see [Direct connection](/docs/guides/database/connecting-to-postgres#direct-connection).

## Log slow queries

`log_min_duration_statement` logs each statement that runs longer than a threshold. It records the statement and its duration, and nothing else, so it's lighter than logging query plans.

```sql
alter role "postgres" set "log_min_duration_statement" to '2s';
```

A slow statement produces a log like this:

```sh
duration: 1.097 ms statement: select * from example_table limit 100;
```

## Log the query plans of slow queries

[auto_explain](https://www.postgresql.org/docs/current/auto-explain.html) is a Postgres module installed on every Supabase project. It logs the statement and the [query plan](https://www.postgresql.org/docs/current/sql-explain.html) of each query that runs longer than a threshold.

```sql
alter role "postgres" set "auto_explain.log_min_duration" to '2s';
```

A slow query produces a log like this:

```sh
duration: 1661.934 ms plan: Query Text: SELECT * FROM example;
Seq Scan on example (cost=0.00..1443.00 rows=100000 width=36)
```

`auto_explain.log_min_duration` is the main setting in a family. Others, such as `auto_explain.log_analyze` and `auto_explain.log_buffers`, control how much detail the plan records. For the full list, see the [auto_explain docs](https://www.postgresql.org/docs/current/auto-explain.html).

## Log the query behind an error

When Postgres logs an event, it also records subfields, such as the [error code](https://www.postgresql.org/docs/current/errcodes-appendix.html). `log_min_error_statement` decides whether the query that caused the event is recorded too, in the `query` subfield. Postgres records the query when the event is as severe as the setting or more. For the severity levels, see [`log_min_messages`](/docs/guides/database/postgres/postgres-log-config#logminmessages).

```sql
alter role "postgres" set "log_min_error_statement" to 'error';
```

A failed insert produces a log like this:

```sh
duplicate key value violates unique constraint "example_pkey"
...
query: "insert into example (id) values (1), (1);
```

## Turn logging off

To remove a setting from a role, reset it to its default:

```sql
alter role "postgres" set "log_min_duration_statement" to default;
```

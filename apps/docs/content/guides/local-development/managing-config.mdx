The Supabase CLI uses a `config.toml` file to manage local configuration. This file is located in the `supabase` directory of your project.

## Config reference

The `config.toml` file is automatically created when you run `supabase init`.

There are a wide variety of options available, which can be found in the [CLI Config Reference](/docs/guides/local-development/cli/config).

For example, to enable the "Apple" OAuth provider for local development, you can append the following information to `config.toml`:

```toml
[auth.external.apple]
enabled = false
client_id = ""
secret = ""
redirect_uri = "" # Overrides the default auth redirectUrl.
```

## Using secrets inside config.toml

You can reference environment variables within the `config.toml` file using the `env()` function. This will detect any values stored in an `.env` file at the root of your project directory. This is particularly useful for storing sensitive information like API keys, and any other values that you don't want to check into version control.

```
.
├── .env
├── .env.example
└── supabase
    └── config.toml
```

<Admonition type="danger">

Do NOT commit your `.env` into git. Be sure to configure your `.gitignore` to exclude this file.

</Admonition>

For example, if your `.env` contained the following values:

```bash
GITHUB_CLIENT_ID=""
GITHUB_SECRET=""
```

Then you would reference them inside of our `config.toml` like this:

```toml
[auth.external.github]
enabled = true
client_id = "env(GITHUB_CLIENT_ID)"
secret = "env(GITHUB_SECRET)"
redirect_uri = "" # Overrides the default auth redirectUrl.
```

## Pushing config to a hosted project

`config.toml` also configures your hosted project. [`supabase config push`](/docs/reference/cli/supabase-config-push) writes the properties your file declares to the linked project through the Management API. This lets you keep Auth, API, database, and Storage settings in version control instead of changing them in the Dashboard.

### What a push changes

- Only properties that `config.toml` declares are written. A property the file doesn't declare keeps its hosted value. `supabase config diff` lists such a property as `remote-only`, for information.
- A declared value replaces the hosted value, including a value set in the Dashboard. For example, `[auth.external.google]` with `enabled = false` disables Google sign-in on the hosted project, even if it is enabled in the Dashboard.
- Some endpoints require a group of properties together, such as the SMTP settings, captcha, and each OAuth provider. When one member of a group changes, the CLI sends the whole group, using the project's current value for the members you don't declare, so those keep their hosted value. If the platform doesn't report a member's current value, the CLI sends the schema default and marks it as `[group-write]` in the confirmation output.
- Before each write, the CLI prints the change for the affected resource (`api`, `db.settings`, `db.network_restrictions`, `db.ssl_enforcement`, `auth`, `storage`) and asks for confirmation.

<Admonition type="caution">

The file that `supabase init` generates declares local development values, such as `site_url = "http://127.0.0.1:3000"`, `minimum_password_length = 6`, and OAuth providers with `enabled = false`. Pushing it unchanged applies those values to the hosted project and reverts settings made in the Dashboard. Preview the diff before you push, and confirm only the changes you expect.

</Admonition>

### Preview and push

1. Link the project:

   ```bash
   supabase link --project-ref <project-id>
   ```

2. If the hosted project was configured in the Dashboard, pull its configuration into `config.toml` first, so the file starts from the hosted values:

   ```bash
   supabase config pull
   ```

3. Preview what a push would change, without writing anything:

   ```bash
   supabase config diff
   ```

4. Push, and confirm each resource:

   ```bash
   supabase config push
   ```

To verify the hosted Auth settings after a push, open Authentication settings in the Dashboard or call [Get auth service config](/docs/reference/api/v1-get-auth-service-config) in the Management API.

`config diff`, `config pull`, and per-resource confirmation are available from CLI v2.117.0. Update the CLI before you follow these steps.

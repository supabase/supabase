---
title: 'Access control'
description: 'Roles and permissions at the organization and project levels'
---

Supabase provides granular access controls for your organizations and projects.

For each organization and project, a member can have one of the following roles:

- **Owner**: full access to everything in organization and project resources.
- **Administrator**: full access to everything in organization and project resources **except** updating organization settings, transferring projects outside of the organization, and adding new owners.
- **Developer**: read-only access to organization resources and content access to project resources but cannot change any project settings.
- **Read-only**: read-only access to organization and project resources.
- **No-access**: no access to any organization or project resources by default. Use it for members who need to see only the projects where they have a [project-scoped role](#organization-scoped-roles-vs-project-scoped-roles).

<Admonition type="note">

The **Read-only** and **No-access** roles are available only on the [Team and Enterprise plans](/pricing).

</Admonition>

When you create an account, Supabase creates a default organization and makes you its **Owner**. You're also the **Owner** of any organization you create.

## Organization scoped roles vs project scoped roles

<Admonition type="note">

Project-scoped roles are available only on the [Team and Enterprise plans](/pricing).

</Admonition>

You can give each member a role scoped to the entire organization or to specific projects.

- If a member has an organization-level role, they have its permissions in all current and future projects in the organization.
- If a member has a project-scoped role, they can access only the projects they're assigned to. In the Supabase Dashboard, they can't see the organization's other projects.

To give a member no project access by default and grant access project by project, assign them the organization-level **No-access** role. Then grant project-scoped roles on the projects they need.

## Manage organization members

You can invite members, change their roles, and list them in your organization's [team settings](/dashboard/org/_/team) or with the [Management API](/docs/reference/api/introduction).

<Admonition type="note">

The Management API endpoints for creating invites and changing roles are available only on the [Team and Enterprise plans](/pricing). Listing members works on every plan.

</Admonition>

The Management API examples in this section use the following variables:

```bash
# Get your access token from https://supabase.com/dashboard/account/tokens
export SUPABASE_ACCESS_TOKEN="your-access-token"
# Find your organization slug in your organization's general settings
export ORG_SLUG="your-organization-slug"
```

Each example names the permission a scoped access token needs. For more information, see [Permission scopes](/docs/guides/platform/personal-access-tokens#permission-scopes).

### Invite a member

An invite is valid for 24 hours. The person gets access only after they accept it.

To invite someone in the Supabase Dashboard:

1. In your organization's [team settings](/dashboard/org/_/team), click **Invite members**.
2. Select a **Role**.
3. To limit the role to one project, turn off **Grant this role on all projects**. In **Select a project**, select the project. An invite can grant a project-scoped role on only one project.
4. In **Email addresses**, enter the person's email address.
5. Click **Send invitation**.

After the person accepts, you can assign roles on more projects.

If an invite expires before the person accepts it, send a new one. Next to the invite, click **More options**, then click **Resend invitation**.

<Admonition type="note">

Only a SAML SSO account from the same identity provider can accept an invite sent from a SAML SSO account.

This security measure prevents accidental invites to accounts that your enterprise's identity provider doesn't manage.

</Admonition>

To invite someone with the Management API, call [Create organization invitations](/docs/reference/api/v2-create-organization-invitations). The token needs the **Organization Members** permission with **Read-write** access. Set `role` to `owner`, `administrator`, `developer`, `read-only`, or `no-access`.

Without `projects`, the role applies to the whole organization:

```bash
curl -X POST "https://api.supabase.com/v2/organizations/$ORG_SLUG/members/invitations" \
  -H "Authorization: Bearer $SUPABASE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "data": [
      {
        "type": "organization_invitation",
        "attributes": { "email": "person@example.com", "role": "developer" }
      }
    ]
  }'
```

To limit the role to a project, add `projects` with the project's reference ID:

```bash
curl -X POST "https://api.supabase.com/v2/organizations/$ORG_SLUG/members/invitations" \
  -H "Authorization: Bearer $SUPABASE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "data": [
      {
        "type": "organization_invitation",
        "attributes": {
          "email": "person@example.com",
          "role": "developer",
          "projects": [{ "ref": "your-project-ref" }]
        }
      }
    ]
  }'
```

### Change a member's role

You can change a member's role after they accept their invite.

To change a member's role in the Supabase Dashboard:

1. In your organization's [team settings](/dashboard/org/_/team), next to the member, click **Manage access**.
2. Choose where the role applies:
   - To give the member one role across the organization, turn on **Apply roles to all projects in the organization**, then select the role.
   - To limit the member to specific projects, turn off **Apply roles to all projects in the organization**. Click **Add project**, select a project, and select a role for it. Repeat for each project.
3. Click **Save roles**. In the confirmation dialog, click **Update roles**.

The Supabase Dashboard replaces the member's previous roles with the roles you save.

To change a member's role with the Management API, call [Assign organization member role](/docs/reference/api/v2-assign-organization-member-role) with the member's user ID. The token needs the **Organization Settings** permission with **Read-write** access. To find a member's user ID, list the organization's members.

Without `projects`, the call assigns an organization-wide role:

```bash
export USER_ID="member-user-id"

curl -X PATCH "https://api.supabase.com/v2/organizations/$ORG_SLUG/members/$USER_ID/roles" \
  -H "Authorization: Bearer $SUPABASE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "data": {
      "type": "organization_member_role",
      "attributes": { "role": "read-only" }
    }
  }'
```

With `projects`, the call assigns a project-scoped role:

```bash
curl -X PATCH "https://api.supabase.com/v2/organizations/$ORG_SLUG/members/$USER_ID/roles" \
  -H "Authorization: Bearer $SUPABASE_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "data": {
      "type": "organization_member_role",
      "attributes": {
        "role": "developer",
        "projects": [{ "ref": "your-project-ref" }]
      }
    }
  }'
```

After a change, [list the member's roles](#list-organization-members-with-the-management-api) to check which roles and projects they have.

### List organization members with the Management API

To list members and their roles, call [List organization members](/docs/reference/api/v2-list-organization-members). The token needs the **Organization Members** permission with **Read** access.

```bash
curl "https://api.supabase.com/v2/organizations/$ORG_SLUG/members" \
  -H "Authorization: Bearer $SUPABASE_ACCESS_TOKEN"
```

Each member's `roles` array shows every role they have. A role's `scope` is `organization` or `project`, and a project-scoped role lists the projects it applies to:

```json
{
  "roles": [
    {
      "name": "developer",
      "scope": "project",
      "projects": [{ "ref": "abcdefghijklmnopqrst", "name": "staging" }]
    }
  ]
}
```

The results are paginated. The endpoint's reference page lists the pagination parameters.

### Transfer ownership of an organization

Each Supabase organization must have at least one **Owner**. If you're the only **Owner**, make another member an **Owner** before you leave. Members with the **Administrator** role can't take over, because they can't update organization settings or add **Owners**.

To leave an organization:

1. If you're the only **Owner**, make another member an **Owner** in one of these ways:
   - Promote an existing member. In team settings, next to the member, click **Manage access**. Turn on **Apply roles to all projects in the organization**, select **Owner**, and save the roles. With the Management API, [assign the role](#change-a-members-role) `owner` without `projects`.
   - Invite someone as **Owner**, and wait for them to accept.
2. In your organization's team settings, click **Leave team**.

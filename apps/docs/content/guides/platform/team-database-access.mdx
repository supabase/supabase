Let a team member connect to your project database as a [Postgres role](/docs/guides/database/postgres/roles) with their own access token, and limit that access by expiry and network. To learn how to enable temporary access and connect with it, see [Temporary access](/docs/guides/platform/temporary-access).

A mapping authorizes a team member to assume one or more existing Postgres roles. It creates no new role or user in the database, and the assumed role's permissions still apply. The role's own password keeps working, so long-lived service connections don't change.

## Before you begin

- [Enable temporary access](/docs/guides/platform/temporary-access#manage-temporary-access-via-the-dashboard) on the project.
- Create a [personal access token](/dashboard/account/tokens) to call the Management API.

## Authorize a team member

1. Set your access token and project ref:

   ```bash
   export SUPABASE_MANAGEMENT_API_TOKEN="your-access-token"
   export PROJECT_REF="your-project-ref"
   export MEMBER_USER_ID="the-member-user-id"
   ```

   `MEMBER_USER_ID` is the user ID of the team member you want to authorize.

2. Map the team member to the roles they can assume. This example authorizes the `postgres` role:

   ```bash
   curl -X PUT "https://api.supabase.com/v1/projects/$PROJECT_REF/database/jit" \
     -H "Authorization: Bearer $SUPABASE_MANAGEMENT_API_TOKEN" \
     -H "Content-Type: application/json" \
     -d @- <<EOF
   {
     "user_id": "$MEMBER_USER_ID",
     "user_roles": [{ "role": "postgres" }]
   }
   EOF
   ```

The team member can now connect as the `postgres` role, with their access token as the password. For connection strings, see [Using temporary access](/docs/guides/platform/temporary-access#using-temporary-access).

## Restrict a team member's access

Each role in the mapping takes two optional restrictions:

- `expires_at`: a Unix timestamp. After it passes, the database rejects the connection, even if the access token is still valid.
- `allowed_networks`: the CIDR ranges the team member can connect from. Put IPv4 ranges in `allowed_cidrs` and IPv6 ranges in `allowed_cidrs_v6`.

This example limits the `postgres` role to one IPv4 address until a fixed time:

```bash
curl -X PUT "https://api.supabase.com/v1/projects/$PROJECT_REF/database/jit" \
  -H "Authorization: Bearer $SUPABASE_MANAGEMENT_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d @- <<EOF
{
  "user_id": "$MEMBER_USER_ID",
  "user_roles": [
    {
      "role": "postgres",
      "expires_at": 1758721065775,
      "allowed_networks": {
        "allowed_cidrs": [{ "cidr": "176.1.12.1/32" }]
      }
    }
  ]
}
EOF
```

Transfer a project to another organization to change who pays for it, to hand it to a client, or to move it to a different plan. A transfer changes the project's organization. The project keeps its data, default URL, and API keys.

## Overview

The _source organization_ is the organization the project belongs to before the transfer. The _target organization_ is the organization you move the project to.

Before you start, check what a transfer changes for downtime, billing, and access in [Changes after a project transfer](/docs/guides/platform/project-transfer/what-changes).

## Prerequisites

Before you transfer a project, check that you meet the following requirements:

- You're an **Owner** of the source organization. Check your role in the organization's [team settings](/dashboard/org/_/team).
- You're a member of the target organization with a [role for the whole organization](/docs/guides/platform/project-transfer/requirements#account-requirements).
- You use the same account in both organizations.
- Nothing [blocks the transfer](/docs/guides/platform/project-transfer/requirements#project-and-organization-requirements), such as a GitHub connection, an overdue invoice in a Free Plan or Pro Plan organization, or a feature that the target organization lacks.

For every requirement and what to do when one isn't met, see [Project transfer requirements](/docs/guides/platform/project-transfer/requirements).

To follow the Management API path, you also need an [access token](/dashboard/account/tokens). For a scoped token, under **Resource access**, select **Organization**, choose both the source and the target organization, and grant the following permissions:

- **Project Settings** with **Read** access, for the preview
- **Organization Settings** with **Read-write** access, for the transfer
- **Organization Members** with **Read** access, for the check on the target organization

A token with **Project** access can't preview or transfer a project. For more information, see [Personal access tokens](/docs/guides/platform/personal-access-tokens).

## Procedure

Transfer one project at a time. To transfer several projects, repeat the steps for each project. The Supabase CLI has no transfer command.

If a check blocks the transfer, see [Troubleshoot a project transfer](/docs/guides/platform/project-transfer/troubleshooting) for the cause and the fix of each message.

<Tabs scrollable size="small" type="underlined" defaultActiveId="dashboard" queryGroup="method">
<TabPanel id="dashboard" label="Dashboard">

To transfer a project in the Supabase Dashboard, follow these steps:

1. Open the project's [general settings](/dashboard/project/_/settings/general).
2. In the **Transfer project** section, click **Transfer project**.
3. In **Select Target Organization**, select the organization to move the project to.
4. Read the result of the checks, which run when you select the target organization. A **Project cannot be transferred** box lists what blocks the transfer. Warnings list what the transfer changes or removes, such as add-ons, compute size, costs, or a Vercel connection. **Transfer Project** stays disabled until every check passes.
5. Click **Transfer Project**.

   <Admonition type="caution">

   A transfer to a Free Plan organization removes add-ons, and transferring the project back doesn't restore them. A transfer has no undo. To move a project back, transfer it again, which runs the same checks.

   </Admonition>

<TabPanel id="api" label="Management API">

To transfer a project with the Management API, follow these steps:

1. Set the token, the project ref, and the target organization's slug. The project ref is the **Project ID** in the project's [general settings](/dashboard/project/_/settings/general), and the slug is the **Organization slug** in the target organization's [general settings](/dashboard/org/_/general). Replace `YOUR_ACCESS_TOKEN`, `YOUR_PROJECT_REF`, and `YOUR_TARGET_ORG_SLUG` with your values:

   ```bash
   export SUPABASE_ACCESS_TOKEN="YOUR_ACCESS_TOKEN"
   export PROJECT_REF="YOUR_PROJECT_REF"
   export TARGET_ORG_SLUG="YOUR_TARGET_ORG_SLUG"
   ```

2. Preview the transfer:

   ```bash
   curl -X POST "https://api.supabase.com/v2/projects/$PROJECT_REF/transfers/previews" \
     -H "Authorization: Bearer $SUPABASE_ACCESS_TOKEN" \
     -H "Content-Type: application/json" \
     -d @- <<EOF
   {
     "data": {
       "type": "project_transfer_input",
       "attributes": { "target_organization_slug": "$TARGET_ORG_SLUG" }
     }
   }
   EOF
   ```

   The response has a `valid` field under `data.attributes`, next to lists of `errors`, `warnings`, and `info` messages. Continue when `valid` is `true`.

3. Transfer the project:

   <Admonition type="caution">

   A transfer to a Free Plan organization removes add-ons, and transferring the project back doesn't restore them. A transfer has no undo. To move a project back, transfer it again, which runs the same checks.

   </Admonition>

   ```bash
   curl -X POST "https://api.supabase.com/v2/projects/$PROJECT_REF/transfers" \
     -H "Authorization: Bearer $SUPABASE_ACCESS_TOKEN" \
     -H "Content-Type: application/json" \
     -d @- <<EOF
   {
     "data": {
       "type": "project_transfer_input",
       "attributes": { "target_organization_slug": "$TARGET_ORG_SLUG" }
     }
   }
   EOF
   ```

   A successful transfer returns `200` with an empty body.

For the full request and response schemas, see [Preview a project transfer](/docs/reference/api/v2-preview-a-project-transfer) and [Transfer a project](/docs/reference/api/v2-transfer-a-project) in the Management API reference.

</TabPanel>
</Tabs>

The project now belongs to the target organization.

## Verify

To confirm that the transfer worked, check which organization the project belongs to.

<Tabs scrollable size="small" type="underlined" defaultActiveId="dashboard" queryGroup="method">
<TabPanel id="dashboard" label="Dashboard">

To check the project's organization in the Dashboard, follow these steps:

1. Open the list of [your organizations](/dashboard/organizations), and select the target organization.
2. Check that the project appears in the organization's list of projects.

</TabPanel>
<TabPanel id="api" label="Management API">

To check the project's organization with the Management API, follow these steps:

1. Request the project. Replace `YOUR_ACCESS_TOKEN` and `YOUR_PROJECT_REF` with your values, or leave out the two `export` lines if you set the variables for the transfer:

   ```bash
   export SUPABASE_ACCESS_TOKEN="YOUR_ACCESS_TOKEN"
   export PROJECT_REF="YOUR_PROJECT_REF"

   curl "https://api.supabase.com/v1/projects/$PROJECT_REF" \
     -H "Authorization: Bearer $SUPABASE_ACCESS_TOKEN"
   ```

2. Check that `organization_slug` in the response is the target organization's slug.

</TabPanel>
</Tabs>

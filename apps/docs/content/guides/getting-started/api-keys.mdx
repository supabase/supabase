Get your Supabase publishable and secret keys, then use the right one in your client, your backend, and your Edge Functions. When you finish, each part of your app calls your project with a key that matches where it runs.

## Overview

Every request to your project carries an API key. Use the publishable key in code you ship and the secret key in code you control. To learn how keys map to Postgres roles and Row Level Security, see [How API keys work](/docs/guides/getting-started/how-api-keys-work).

| Where the code runs                                   | Use this key    |
| ----------------------------------------------------- | --------------- |
| Anything you ship: browser, mobile app, CLI, script   | Publishable key |
| Anything you control: server, Edge Function, cron job | Secret key      |

To replace legacy keys in an application that already ships them, see [Migrating to new API keys](/docs/guides/getting-started/migrating-to-new-api-keys).

## Prerequisites

- **A Supabase project.** [Create one](/dashboard/new/_) if you don't have one.
- **A signed-in Dashboard session.** [Sign in](/dashboard/projects) to copy your keys.
- **A publishable key and a secret key.** Create them in [**Settings > API Keys**](/dashboard/project/_/settings/api-keys/).

## Procedure

You will name your variables, copy your keys, then use them in client, backend, and Edge Function code.

### 1. Set your variable names

Your code reads keys by name, so add the names before the values.

1. Add the browser-safe names, prefixed as your framework requires:

   ```bash .env
   NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
   ```

2. Add the server-only names, with no prefix so your bundler never ships them:

   ```bash .env
   SUPABASE_URL=https://your-project.supabase.co
   SUPABASE_SECRET_KEY=sb_secret_...
   ```

### 2. Copy your keys

Copy the values from the Dashboard. To use the CLI, the Management API, or a local stack instead, see [Get your keys](/docs/guides/getting-started/api-keys-reference#get-your-keys).

1. Open your project's [**Connect** dialog](/dashboard/project/_?showConnect=true) and copy the URL and publishable key.

2. Open [**Settings > API Keys**](/dashboard/project/_/settings/api-keys/) and copy the secret key.

3. Paste each value into `.env` under the names from phase 1.

### 3. Use the publishable key in client code

Use the publishable key in any code that reaches a user's device.

1. Open the file where you create your client, such as `lib/supabase.ts`.

2. Pass the publishable key to `createClient`:

   ```ts lib/supabase.ts
   import { createClient } from '@supabase/supabase-js'

   export const supabase = createClient(
     process.env.NEXT_PUBLIC_SUPABASE_URL!,
     process.env.NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY!
   )
   ```

3. Enable Row Level Security on every table before you deploy. See [Limits of publishable keys](/docs/guides/getting-started/how-api-keys-work#limits-of-publishable-keys).

### 4. Use the secret key in backend code

Use the secret key only in code that never reaches a user's device.

1. Open the server-only file where you create your admin client, such as `server/supabase.ts`.

2. Pass the secret key to `createClient`:

   ```ts server/supabase.ts
   import { createClient } from '@supabase/supabase-js'

   export const supabaseAdmin = createClient(
     process.env.SUPABASE_URL!,
     process.env.SUPABASE_SECRET_KEY!
   )
   ```

### 5. Use the secret key in an Edge Function

Use the [`@supabase/server`](/docs/guides/functions/auth) SDK, which gives your function a privileged client without exposing the key. To read the key from the environment instead, see [Edge Functions](/docs/guides/getting-started/api-keys-reference#edge-functions).

1. Wrap your handler in `withSupabase` and use the client on `ctx`:

   ```ts supabase/functions/roster/index.ts
   import { withSupabase } from 'npm:@supabase/server@1'

   export default {
     fetch: withSupabase({ auth: 'secret' }, async (_req, ctx) => {
       const { data } = await ctx.supabaseAdmin.from('profiles').select('email')
       return Response.json({ data })
     }),
   }
   ```

2. Turn off JWT verification for the function, because it's called with a secret key:

   ```toml supabase/config.toml
   [functions.roster]
   verify_jwt = false
   ```

## Verify

Confirm your client reaches your project with the publishable key.

1. Run a query from your client, such as `supabase.from('your_table').select()`.

2. Check the result. A result, or an empty list, means the key works. An authentication error means the key is wrong or missing.

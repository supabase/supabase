## Usage

Once you install the block in your Next.js project, you'll get all the necessary pages and components to set up a magic link authentication flow.

### Getting started

After installing the block, you'll have the following environment variables in your `.env.local` file:

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
```

- If you're using supabase.com, you can find these values in the [Connect modal](https://supabase.com/dashboard/project/_?showConnect=true&connectTab=frameworks&framework=nextjs) under App Frameworks or in your project's [API settings](https://supabase.com/dashboard/project/_/settings/api).

- If you're using a local instance of Supabase, you can find these values by running `supabase start` or `supabase status` (if you already have it running).

### Adding email templates

Add an [email template for magic link](https://supabase.com/dashboard/project/_/auth/templates) to the Supabase project. Your magic link email template should contain at least the following HTML:

```html
<h2>Log in to your account</h2>

<p>Follow the link below to log in. This link is valid for a single use.</p>
<p>
  <a
    href="{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=email&next={{ .RedirectTo }}"
    >Log in</a
  >
</p>
```

For detailed instructions on how to configure your email templates, including the use of variables like `{{ .SiteURL }}`,`{{ .TokenHash }}`, and `{{ .RedirectTo }}`, refer to our [Email Templates guide](https://supabase.com/docs/guides/auth/auth-email-templates).

### Setting up routes and redirect URLs

1. Set the site URL in the [URL Configuration](https://supabase.com/dashboard/project/_/auth/url-configuration) settings in the Supabase Dashboard.
1. Go to the [URL Configuration](https://supabase.com/dashboard/project/_/auth/url-configuration) settings and add the route users land on after following the magic link to the list of Redirect URLs. Our examples use `/protected`, so it should look something like: `http://example.com/protected`.

1. Update the redirect path in the `magic-link-form.tsx` component to point to the logged-in route in your app. Our examples use `/protected`, but you can set this to whatever fits your app.

<Callout type="info">

You can use this block with the Pages router by moving the routes from the `app` folder into the `pages` folder and renaming them. Example instead of `app/auth/login/page.tsx`, you'd create a `pages/auth/login.tsx` file.

</Callout>

### Combining magic link auth with password-based auth

If you want to combine this block with the [password-based auth block](/ui/docs/nextjs/password-based-auth), copy the `handleMagicLink` function into the password-based `login-form.tsx` component and bind it to a "Send magic link" button. Both blocks share the same `app/auth/confirm/route.ts` handler.

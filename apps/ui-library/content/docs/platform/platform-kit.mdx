## Introduction

The Platform Kit is a collection of customizable hooks and components you can use to provide an embedded Supabase experience within your own platform. It ships a single dialog for managing your database, authentication, storage, users, secrets, logs, and performance monitoring.

It is fully client-side and framework-agnostic (React + Vite, wouter for in-dialog routing). Data, auth, and storage go through `@supabase/supabase-js`; schema introspection goes through PostgREST. A pluggable **adapter** decides which backend the dialog talks to and which features are available, so the same UI works against hosted Supabase and [supalite](https://github.com/supabase/lite).

**Features**

- Database, Auth, Storage, User, Secrets, Logs, and Performance management
- Responsive dialog/drawer interface (desktop & mobile)
- Adapter-driven: works with Supabase or supalite, or bring your own
- Feature flags: panels show/hide based on what the adapter supports
- Natural-language SQL generation (optional)

## Who is it for

Anyone who is providing Postgres databases to their users.

## Usage

Pass an adapter to the dialog. The bundled `createSupabaseAdapter` takes a `supabase-js` client:

```tsx
import { createClient } from '@supabase/supabase-js'
import { useState } from 'react'

import SupabaseManagerDialog from '@/components/supabase-manager'
import { Button } from '@/components/ui/button'
import { createSupabaseAdapter } from '@/lib/adapter/create-supabase-adapter'

const supabase = createClient(import.meta.env.VITE_SUPABASE_URL, import.meta.env.VITE_SUPABASE_KEY)

const adapter = createSupabaseAdapter({
  supabase,
  projectRef: 'your-project-ref',
})

export default function Example() {
  const [open, setOpen] = useState(false)

  return (
    <>
      <Button onClick={() => setOpen(true)}>Open Supabase Manager</Button>
      <SupabaseManagerDialog adapter={adapter} open={open} onOpenChange={setOpen} />
    </>
  )
}
```

With only a `supabase` client, the kit is entirely client-side: database (introspection + row editing), users, and storage work out of the box. Management-only panels (Auth config, Logs, Secrets, Suggestions, and the SQL editor) light up when you supply your own Management API transport — a route in your app that injects the Management API token server-side so it never reaches the browser:

```tsx
const adapter = createSupabaseAdapter({
  supabase,
  projectRef: 'your-project-ref',
  // Your own trusted proxy that forwards to https://api.supabase.com with the token attached.
  management: { baseUrl: '/api/supabase-proxy', projectRef: 'your-project-ref' },
  // Optional: your own natural-language → SQL endpoint.
  generateSql: async (prompt) => {
    const res = await fetch('/api/ai/sql', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ prompt }),
    })
    return res.json()
  },
})
```

### supalite

Point the same dialog at a local [supalite](https://github.com/supabase/lite) instance with `createSupaliteAdapter`. It introspects via supalite's `/_system/introspect` and reads/writes rows through supabase-js. Management-only features are hidden automatically.

```tsx
import { createClient } from '@supabase/supabase-js'

import { createSupaliteAdapter } from '@/lib/adapter/create-supalite-adapter'

const supabase = createClient(window.location.origin, 'any-string-works-for-now')

const adapter = createSupaliteAdapter({
  supabase,
  enableStorage: false, // set true if supalite EXPERIMENTAL_STORAGE is on
})
```

### Toaster

Add a `Toaster` at the root of your app for notifications:

```tsx
import { Toaster } from '@/components/ui/sonner'

export default function App({ children }) {
  return (
    <>
      {children}
      <Toaster />
    </>
  )
}
```

## Custom adapters

Any object matching the `PlatformAdapter` interface (`lib/adapter/types.ts`) can be passed to the dialog. The `features` flag map on the adapter drives which panels and controls render, so a custom adapter can expose exactly the capabilities your backend supports.

## Security

- Never expose your Management API token to the client. Put it behind your own proxy and point the adapter's `management.baseUrl` at it.
- The `supabase-js` client uses whatever key your security model allows — a `service_role` key only in trusted or local contexts, otherwise an anon key with RLS.

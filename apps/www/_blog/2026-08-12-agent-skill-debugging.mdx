The [Supabase agent skill](https://github.com/supabase/agent-skills) now includes a debugging workflow. Install it, and the next time your agent hits a Supabase error, it stops guessing and starts investigating.

## Why install it

Claude Code, Cursor, and other coding agents connect to Supabase through the [Supabase MCP server](https://supabase.com/docs/guides/getting-started/mcp) or the CLI, so they debug your project as often as they write code for it. Left on their own, agents default to the same failure mode: a broad, all-source log scan with no time bound and no filter. That buries the one line that matters, floods the agent's context, and on paid projects runs up the data scanned.

With the skill installed, your agent instead reproduces the error, isolates which Supabase service caused it, and runs one narrow log query against that exact source before proposing a fix. The approach comes straight from Supabase's own [Debugging guide](https://supabase.com/docs/guides/monitoring-and-debugging/debugging), so it stays current as that guide is updated, without needing a new version of the skill.

## What you get

- **Root-cause fixes, not symptom patches.** The agent isolates the layer that actually failed (Auth, the Data API, Realtime, Storage, Edge Functions, or Postgres itself) instead of pattern-matching the error message.
- **Cheaper, faster log queries.** Narrow, filtered queries through the `query_logs` MCP tool replace an unfiltered dump across every log source.
- **A workflow that doesn't go stale.** The skill points at Supabase's troubleshooting guides rather than carrying its own copy, so it updates automatically as those guides do.
- **No new tool to learn.** It works with any agent already connected through the Supabase MCP server or CLI.

## How to install it

```bash
npx skills add supabase/agent-skills
```

Then ask your agent to debug whatever's broken, no extra setup required.

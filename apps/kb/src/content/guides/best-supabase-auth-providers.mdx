Authentication is the part of an app that decides who a user is before any data is read or written.

You can use these providers with Supabase through [third-party auth](/docs/guides/auth/third-party/overview), alongside Supabase Auth or on their own. Supabase accepts their JSON Web Tokens (JWTs) to access the [Data API (REST and GraphQL)](/docs/guides/api), [Storage](/docs/guides/storage), [Realtime](/docs/guides/realtime), and [Edge Functions](/docs/guides/functions).

## Supabase Auth

[Supabase Auth](/docs/guides/auth) is the built-in authentication service for Supabase projects. It supports email and password sign-in, magic links, phone sign-in, OAuth providers, and more. Its tokens work directly with the Data API, Storage, and Row Level Security policies without an extra integration step.

If you are starting a new Supabase project, Supabase Auth is the best fit.

## Clerk

Clerk is a user management platform for web and mobile apps. It provides prebuilt sign-in components, session management, and organization support for multi-tenant apps.

If you already have a production app using Clerk and want to use the rest of the Supabase Platform, see the [Clerk integration with Supabase](/docs/guides/auth/third-party/clerk).

## Firebase Auth

Firebase Auth is Google's identity service within the Firebase platform. It supports email and password, phone, and federated sign-in with social providers.

If you already have a production app using Firebase Auth and want to use the rest of the Supabase Platform, see the [Firebase Auth integration with Supabase](/docs/guides/auth/third-party/firebase-auth).

> [!NOTE]
> If you want to migrate from Firebase Auth to Supabase Auth, see the [Firebase Auth migration guide](/kb/guides/migrate-from-firebase-auth).

## Auth0

Auth0, owned by Okta, is an identity platform for consumer and enterprise apps. It offers hosted sign-in pages, social and enterprise connections, and multi-factor authentication.

If you already have a production app using Auth0 and want to use the rest of the Supabase Platform, see the [Auth0 integration with Supabase](/docs/guides/auth/third-party/auth0).

> [!NOTE]
> If you want to migrate from Auth0 to Supabase Auth, see the [Auth0 migration guide](/kb/guides/migrate-from-auth0).

## Amazon Cognito

Amazon Cognito is AWS's identity service. Its user pools handle sign-up and sign-in, and it works with AWS Amplify on the client. It fits teams whose infrastructure already runs on AWS.

If you already have a production app using Amazon Cognito and want to use the rest of the Supabase Platform, see the [Amazon Cognito integration with Supabase](/docs/guides/auth/third-party/aws-cognito).

## WorkOS

WorkOS provides enterprise features for B2B software, including single sign-on, directory sync, and AuthKit for user authentication.

If you already have a production app using WorkOS and want to use the rest of the Supabase Platform, see the [WorkOS integration with Supabase](/docs/guides/auth/third-party/workos).

## Custom OIDC providers

If your identity provider isn't listed here but supports OpenID Connect (OIDC), you can still use it with Supabase. The provider needs to expose an OIDC issuer discovery URL and sign JWTs with an asymmetric key. It must also include a `role` claim set to `authenticated` for signed-in users.

See the [Custom OIDC guide](/docs/guides/auth/third-party/custom-oidc) for the full setup, including the Management API option, client configuration, and Row Level Security policies.

## Other providers

You can also use Supabase as a [standalone Postgres database](/database), entirely separate from the rest of the Supabase Platform. In this case, you can set up your own authentication and authorization flows using any provider.

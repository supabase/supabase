[Better Auth](https://better-auth.com) is an open source authentication library for TypeScript. It stores users, sessions, and accounts in your own database. This guide shows you how to keep those tables in your Supabase Postgres database, and how to manage them with the Supabase CLI and [declarative schemas](/docs/guides/local-development/declarative-database-schemas).

You'll build a [TanStack Start](https://tanstack.com/start) app with email and password sign-in. The database setup works the same in any framework. Only the route handler and client code change, and Better Auth documents those for each framework in its [installation guide](https://better-auth.com/docs/installation#mount-handler).

By the end, you have:

- Better Auth tables in a dedicated `better_auth` schema
- A declarative schema file and a generated migration that you commit to your repository
- A working sign-up, sign-in, and session flow against your local Supabase stack
- The same schema deployed to your hosted Supabase project

> [!NOTE]
> Better Auth replaces [Supabase Auth](/docs/guides/auth) for the users it manages. Supabase Auth features such as `auth.uid()` in Row Level Security (RLS) policies and the auth methods in `supabase-js` don't apply to Better Auth sessions.

## Prerequisites

- [Node.js](https://nodejs.org) 22 or later
- A [Supabase project](/dashboard/project/_), to deploy to

This guide uses Supabase CLI v3. It installs as a development dependency, so you run it with `npx supabase`.

## Create the app

Create a TanStack Start app and move into its directory:

```bash
npx @tanstack/cli@latest create my-app
cd my-app
```

Install Better Auth, the Postgres driver, and Kysely, which Better Auth uses to talk to Postgres:

```bash
npm install better-auth pg kysely
npm install -D @types/pg supabase
```

## Start Supabase locally

Initialize Supabase in your project and start the local stack:

```bash
npx supabase init
npx supabase start
```

When the stack is running, the CLI prints its connection details. The local database URL is:

```text
postgresql://postgres:postgres@127.0.0.1:54322/postgres
```

## Set environment variables

Generate a secret that Better Auth uses to sign session cookies:

```bash
npx auth@latest secret
```

Create a `.env` file in your project root with the secret, the local database URL, and your app's URL:

```bash
DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:54322/postgres
BETTER_AUTH_SECRET=<your-generated-secret>
BETTER_AUTH_URL=http://localhost:3000
```

## Configure Better Auth

Create `src/lib/auth.ts`. This configures Better Auth with the Kysely `PostgresDialect` and keeps its tables in a `better_auth` schema:

```ts
import { betterAuth } from 'better-auth'
import { tanstackStartCookies } from 'better-auth/tanstack-start'
import { PostgresDialect } from 'kysely'
import { Pool } from 'pg'

export const auth = betterAuth({
  database: {
    dialect: new PostgresDialect({
      pool: new Pool({
        connectionString: process.env.DATABASE_URL,
      }),
    }),
    type: 'postgres',
    schemaName: 'better_auth',
  },
  emailAndPassword: {
    enabled: true,
  },
  plugins: [tanstackStartCookies()],
})
```

The `schemaName` option keeps the tables in their own schema, outside of the default schema of the database. Better Auth qualifies every query with the schema name, such as `"better_auth"."user"`.

The `tanstackStartCookies` plugin sets cookies through TanStack Start. Other frameworks don't need it.

## Generate the Better Auth schema

Declarative schema files in `supabase/schemas/` describe the state you want your database to be in. The Supabase CLI compares them with your migrations and writes the difference as a new migration.

Use the Better Auth CLI to write its tables to a schema file:

```bash
mkdir -p supabase/schemas
npx auth@latest generate --output supabase/schemas/better_auth.sql --yes
```

> [!NOTE]
> The command logs a `Database schema mismatch` error that lists missing tables. This is expected. The tables don't exist yet, and the generated file creates them.

The generated file creates the schema and each table with a schema-qualified name:

```sql
create schema if not exists "better_auth";

create table "better_auth"."user" ("id" text not null primary key, "name" text not null, "email" text not null unique, "emailVerified" boolean not null, "image" text, "createdAt" timestamptz default CURRENT_TIMESTAMP not null, "updatedAt" timestamptz default CURRENT_TIMESTAMP not null);

create table "better_auth"."session" ( ... );

create table "better_auth"."account" ( ... );

create table "better_auth"."verification" ( ... );
```

> [!IMPORTANT]
> With the Kysely adapter, `generate` inspects your live database and only outputs what's missing. Run it against a local database that doesn't have the Better Auth tables yet. To add changes later, see [Update the schema](#update-the-schema).

## Generate and apply the migration

Generate a migration from your schema files, then apply it to your local database:

```bash
npx supabase db schema declarative sync -f add_better_auth --no-apply
npx supabase migration up
```

The CLI writes the migration to `supabase/migrations/<timestamp>_add_better_auth.sql`. Review it before you commit it. It starts like this:

```sql
CREATE SCHEMA "better_auth";

CREATE TABLE "better_auth"."account" (
  "id"                    text                     NOT NULL,
  "accountId"             text                     NOT NULL,
  ...
```

Confirm that the database matches what Better Auth expects:

```bash
npx auth@latest check schema
```

The command prints `Schema check passed against the live database.`

Commit both `supabase/schemas/better_auth.sql` and the new migration.

## Mount the auth handler

Better Auth serves its endpoints, such as `/api/auth/sign-up/email`, through a single handler. In TanStack Start, mount it as a server route.

Create `src/routes/api/auth/$.ts`:

```ts
import { createFileRoute } from '@tanstack/react-router'

import { auth } from '@/lib/auth'

export const Route = createFileRoute('/api/auth/$')({
  server: {
    handlers: {
      GET: ({ request }) => auth.handler(request),
      POST: ({ request }) => auth.handler(request),
    },
  },
})
```

## Add sign-up and sign-in

Create the Better Auth client in `src/lib/auth-client.ts`:

```ts
import { createAuthClient } from 'better-auth/react'

export const authClient = createAuthClient()
```

Create a server function that reads the current session from the request cookies in `src/lib/auth.functions.ts`:

```ts
import { createServerFn } from '@tanstack/react-start'
import { getRequestHeaders } from '@tanstack/react-start/server'

import { auth } from '@/lib/auth'

export const getSession = createServerFn({ method: 'GET' }).handler(async () => {
  const headers = getRequestHeaders()
  return auth.api.getSession({ headers })
})
```

Replace `src/routes/index.tsx` with a page that loads the session on the server. It shows a sign-up and sign-in form, or the signed-in user's email:

```tsx
import { createFileRoute, useRouter } from '@tanstack/react-router'
import { useState } from 'react'

import { authClient } from '@/lib/auth-client'
import { getSession } from '@/lib/auth.functions'

export const Route = createFileRoute('/')({
  loader: () => getSession(),
  component: Home,
})

function Home() {
  const session = Route.useLoaderData()
  const router = useRouter()
  const [name, setName] = useState('')
  const [email, setEmail] = useState('')
  const [password, setPassword] = useState('')
  const [error, setError] = useState<string | null>(null)

  if (session) {
    return (
      <main>
        <p>Signed in as {session.user.email}</p>
        <button
          onClick={async () => {
            await authClient.signOut()
            router.invalidate()
          }}
        >
          Sign out
        </button>
      </main>
    )
  }

  async function handleSignUp() {
    const { error } = await authClient.signUp.email({ name, email, password })
    if (error) return setError(error.message ?? 'Sign-up failed')
    router.invalidate()
  }

  async function handleSignIn() {
    const { error } = await authClient.signIn.email({ email, password })
    if (error) return setError(error.message ?? 'Sign-in failed')
    router.invalidate()
  }

  return (
    <main>
      <input placeholder="Name" value={name} onChange={(e) => setName(e.target.value)} />
      <input placeholder="Email" value={email} onChange={(e) => setEmail(e.target.value)} />
      <input
        placeholder="Password"
        type="password"
        value={password}
        onChange={(e) => setPassword(e.target.value)}
      />
      <button onClick={handleSignUp}>Sign up</button>
      <button onClick={handleSignIn}>Sign in</button>
      {error && <p>{error}</p>}
    </main>
  )
}
```

To protect routes and server functions, see [Protecting resources](https://better-auth.com/docs/integrations/tanstack#protecting-resources) in the Better Auth TanStack Start guide.

## Test it locally

Start the dev server:

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000), and sign up with a name, email, and password. The page shows `Signed in as` with your email.

Check that the user is stored in the `better_auth` schema:

```bash
npx supabase db query 'select id, email from better_auth."user"'
```

You can also browse the tables in Studio at [http://127.0.0.1:54323](http://127.0.0.1:54323). In the Table Editor, select the `better_auth` schema.

## Deploy to your Supabase project

Sign in to the Supabase CLI and link your project:

```bash
npx supabase login
npx supabase link
```

Push your migrations to the hosted database. The CLI asks you to confirm before it changes your project:

```bash
npx supabase db push --remote
```

Then set these environment variables where your app runs:

- `DATABASE_URL`: the connection string from your project's [**Connect** panel](/dashboard/project/_?showConnect=true). Choose the connection type based on where your app runs (see the table after this list).
- `BETTER_AUTH_SECRET`: a new secret for production, generated with `npx auth@latest secret`
- `BETTER_AUTH_URL`: your app's public URL

| Where your app runs                                | Connection type                 |
| -------------------------------------------------- | ------------------------------- |
| Serverless functions, such as Vercel or Netlify    | Shared pooler, transaction mode |
| A long-running server on an IPv4-only network      | Shared pooler, session mode     |
| A long-running server with IPv6 or the IPv4 add-on | Direct connection               |

For serverless functions, create the pool once at module scope and set `max: 1` on the `Pool`. Kysely with node-postgres doesn't use prepared statements, so it works with transaction mode without extra settings. See [Connect to your database](/docs/guides/database/connecting-to-postgres) for details on each connection type.

## Update the schema

Better Auth plugins, and some Better Auth upgrades, add tables or columns. Because `generate` inspects your live database, it outputs only the changes. Use it to update your schema file:

1. Make the change in `src/lib/auth.ts`, such as adding a plugin.

1. Generate the changes against your local database, which has the current schema applied. Write them to a temporary file:

   ```bash
   npx auth@latest generate --output better_auth_changes.sql --yes
   ```

   For example, adding the [`username` plugin](https://better-auth.com/docs/plugins/username) generates:

   ```sql
   alter table "better_auth"."user" add column "username" text;

   alter table "better_auth"."user" add column "displayUsername" text;

   create unique index "user_username_uidx" on "better_auth"."user" ("username");
   ```

1. Append the changes to your schema file, and delete the temporary file:

   ```bash
   cat better_auth_changes.sql >> supabase/schemas/better_auth.sql
   rm better_auth_changes.sql
   ```

1. Generate and apply a new migration:

   ```bash
   npx supabase db schema declarative sync -f add_better_auth_username --no-apply
   npx supabase migration up
   ```

1. Deploy it with `npx supabase db push --remote`.

> [!WARNING]
> Don't run `npx auth@latest migrate` in this setup. It changes the database directly. The declarative schema files are the source of truth, so the Supabase CLI doesn't see changes made outside them and won't include them in your migrations.

## Access your app data

Better Auth handles sign-in and sessions. How your app reads and writes its own data is up to you:

- **A Postgres client or ORM on the server**, such as Kysely, Drizzle, or Prisma. Read the user from `auth.api.getSession()`, then filter queries by `session.user.id`.
- **The Supabase Data API**. The Data API and RLS policies identify users from Supabase-issued JSON Web Tokens (JWTs), and Better Auth sessions aren't Supabase JWTs. Using the Data API with per-user RLS needs extra setup that this guide doesn't cover.

To link your own tables to Better Auth users, reference `better_auth."user"(id)`. The ID is `text`:

```sql
create table public.profiles (
  id bigint generated always as identity primary key,
  user_id text not null references better_auth."user" (id) on delete cascade,
  bio text
);
```

Add tables like this to a file in `supabase/schemas/`, then generate a migration with `npx supabase db schema declarative sync`. If a table is in `public` or another exposed schema, enable RLS on it.

Queue providers store messages until a worker is ready to process them. They let your app move slow or failure-prone work, such as sending emails, calling third-party APIs, or processing uploads, out of the request path, and they retry that work if it fails.

## Supabase Queues

[Supabase Queues](/docs/guides/queues) is the best choice if you already use Supabase and want durable background work next to your data, without running another service. It's also a great choice for new projects that need a [Database](/docs/guides/database/overview), [Edge Functions](/docs/guides/functions), [Auth](/docs/guides/auth), or [Storage](/docs/guides/storage).

Supabase Queues is a Postgres-native message queue built on the [pgmq](/docs/guides/queues/pgmq) extension. It includes:

- Guaranteed delivery, with each message delivered exactly once to a consumer within a configurable visibility window.
- Durable storage in Postgres, with optional archiving of processed messages for auditing or analytics.
- Basic queues for durability and unlogged queues for faster, transient work.
- Access control through API permissions and Row Level Security (RLS) policies.
- Queue and message management in the Supabase Dashboard.

Queues are pull-based, so consumers fetch messages when they're ready, including from [Edge Functions](/docs/guides/queues/consuming-messages-with-edge-functions). Because queues live in your database, you can manage them with SQL and any Postgres tooling. For setup, see the [Queues quickstart](/docs/guides/queues/quickstart) and [API reference](/docs/guides/queues/api).

## Amazon SQS

Amazon SQS is AWS's fully managed message queue service, with Standard queues for high throughput and FIFO queues for ordered, deduplicated delivery.

SQS has a free tier, then charges for quantities of specific requests, with separate rates for Standard and FIFO queues.

Choose SQS when your stack is already on AWS and you want a queue that integrates with Lambda, SNS, and IAM.

## Cloudflare Queues

Cloudflare Queues sends and receives messages with guaranteed delivery, integrated with Cloudflare Workers. It supports batching, retries, delays, dead letter queues, and pull consumers over HTTP.

Cloudflare Queues charges for operations and for queues above the included amount on your current Workers plan. It has no charges for egress bandwidth.

Choose Cloudflare Queues when your app already runs on Workers and you want a queue close to your edge code.

## Upstash QStash

Upstash QStash is a serverless messaging and scheduling service that delivers messages to your HTTP endpoints, with retries, delays, and cron-style schedules.

QStash has a free tier, usage-based pricing, and fixed monthly plans.

Choose QStash when you run on serverless or edge platforms and want a queue that calls your HTTP endpoints, so you don't run any long-lived workers.

## CloudAMQP

CloudAMQP is a managed host for RabbitMQ and LavinMQ, which are message brokers built on AMQP.

CloudAMQP offers a free plan for development. Its paid plans are priced per month by plan size, with dedicated plans for larger workloads.

Choose CloudAMQP when you need a full message broker, with features such as flexible routing, multiple messaging patterns, or existing AMQP clients, and don't want to operate RabbitMQ yourself.

## Other options

You can also run a broker yourself, such as RabbitMQ, or use an open-source job queue library such as BullMQ, which runs on Redis or PostgreSQL. This gives you full control, but you run, scale, and secure the infrastructure yourself.

## When to choose

- **Supabase Queues:** you already use Supabase, or you're starting a new project that needs a Database, Edge Functions, Auth, or Storage alongside durable queues.
- **Amazon SQS:** your stack is already on AWS and you want a queue that integrates with Lambda, SNS, and IAM.
- **Cloudflare Queues:** your app already runs on Workers and you want a queue close to your edge code.
- **Upstash QStash:** you run on serverless or edge platforms and want messages delivered to HTTP endpoints, with no workers to run.
- **CloudAMQP:** you need a full message broker such as RabbitMQ, with flexible routing or existing AMQP clients.
- **A self-hosted broker or library such as RabbitMQ or BullMQ:** you want full control over your infrastructure and can run and secure it yourself.

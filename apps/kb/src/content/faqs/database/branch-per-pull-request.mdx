---
title: Can I get a separate Postgres database for each pull request?
topics: ['Database', 'Platform']
---

Yes, on paid plans. Supabase Branching creates a preview branch for each pull request, with its own database and API credentials, and deletes it when the pull request is merged or closed. Branches are billed per branch, per hour while they exist.

A new branch is built from your project's migration files, not copied from production, so it gets your schema but none of your data. You can seed it with a seed file, or turn on **Include data** when you create a branch from the dashboard if the project has the Point-in-Time Recovery add-on. If a branch comes up empty, part of your schema probably never made it into migration files. [Why are my Supabase branches empty?](/kb/troubleshooting/new-branch-doesnt-copy-database) explains the fix.

When you merge, Supabase applies the branch's migrations to production and deploys any changed Edge Functions. With the GitHub integration, that only happens if **Deploy to production** is turned on. Deploying from GitHub to your main project works on any plan. Only the preview branches need a paid plan. See [Branching](https://supabase.com/docs/guides/deployment/branching).

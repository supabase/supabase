## Segmented

A Supabase addition — not part of shadcn or Radix. A segmented control is a small row of mutually
exclusive options sharing one continuous track: a compact switch that changes what is on screen
right now, sitting next to or inside the thing it affects.

<ComponentPreview name="toggle-group-segmented" />

Reach for it when the choice is small, always has an answer, and takes effect immediately. It is
not a form field.

### How it diverges from the defaults

The `segmented` variant deliberately behaves differently from the `default` and `outline` variants
above, which are left exactly as shadcn ships them:

|                  | `default` / `outline`               | `segmented`                                  |
| ---------------- | ----------------------------------- | -------------------------------------------- |
| Border           | `outline` draws one per item        | None — naked by default                      |
| Spacing          | `gap-1` between items               | No gap — one continuous control              |
| Selected state   | Each item paints its own background | A single flat indicator, shared by the group |
| Selection change | Cuts over instantly                 | Indicator slides between segments            |
| Cursor           | Browser default                     | `cursor-pointer`                             |

Nothing here changes the other variants. If you are using `default` or `outline`, this section
does not apply to you.

### Tones

`tone` restyles a segmented group using the Button variant vocabulary. It is a second axis rather
than more `variant` values because `variant` is shadcn's, and its `outline` value is already in
use elsewhere — redefining it would restyle existing callsites.

| `tone`    | Container       | Selected indicator                             |
| --------- | --------------- | ---------------------------------------------- |
| `text`    | None — naked    | `bg-accent` fill                               |
| `outline` | `border-strong` | `bg-overlay-hover` fill, bordered, `shadow-sm` |
| `primary` | None — naked    | Brand fill, matching a primary Button          |

Resting items are identical across all three; only the container and the indicator move.

### Sanctioned uses

Both are single-select, and both set `allowDeselect={false}`.

#### View state

Which representation of the same thing am I looking at — Data or Definition in the table editor,
Table or Chart for a query result. Usually two items. This is the example at the top of this
section.

#### Filter

Narrowing a list to a subset. Always include an explicit **All** segment as the unfiltered state,
and make it the default. Usually three items.

<ComponentPreview name="toggle-group-segmented-filter" peekCode />

### Rules

#### Never use deselection to mean "no filter"

Radix clears the selection when you click the already-active item of a `type="single"` group,
emitting `''` to `onValueChange`. That is right for a toolbar of optional toggles and wrong here:
a segmented control has no "nothing selected" state, and nothing in the control tells the user
that state exists.

Add an **All** segment and set [`allowDeselect={false}`](#allowdeselect).

| Bad                                       | Good                                                  |
| ----------------------------------------- | ----------------------------------------------------- |
| `Active \| Revoked`, deselect to see both | `All \| Active \| Revoked`, `All` selected by default |

#### Two to four items

Past four, the row gets too wide to scan and starts competing with the content it filters. Use a
[Select](../components/select) instead.

#### Not for form fields

Segmented controls are for display state and filters — things that take effect immediately and are
not saved. If the choice is persisted:

| Choice                            | Use                                      |
| --------------------------------- | ---------------------------------------- |
| A saved boolean setting           | [Switch](../components/switch)           |
| A saved mutually exclusive choice | [Radio Group](../components/radio-group) |
| Display state or a filter         | Segmented control                        |

The distinction is whether the control mutates state. A segmented control changes what you are
looking at; a form control changes what is stored. Putting one in a form also breaks the
expectation that nothing is written until submit.

#### Not a replacement for Tabs

If the options swap between substantial panels of content — different forms, different tables,
sections with their own headings — use [Tabs](../components/tabs). Tabs carry the right semantics
for that, and they have room for the longer labels those sections need.

### The sliding indicator

The selected segment is drawn by a single indicator that slides between segments, the same
mechanism [Tabs](../components/tabs) uses for its underline. Items paint no background or border
of their own.

A single-select segmented group renders the indicator for you — there is nothing to add:

```tsx
import { ToggleGroup, ToggleGroupItem } from 'ui'
;<ToggleGroup
  type="single"
  variant="segmented"
  size="tiny"
  value={status}
  onValueChange={setStatus}
  allowDeselect={false}
  aria-label="Filter keys by status"
>
  <ToggleGroupItem value="all">All</ToggleGroupItem>
  <ToggleGroupItem value="active">Active</ToggleGroupItem>
  <ToggleGroupItem value="revoked">Revoked</ToggleGroupItem>
</ToggleGroup>
```

It respects `prefers-reduced-motion`. A `type="multiple"` segmented group gets no indicator, since
one cannot straddle several selected items — those items fall back to painting their own selected
background.

### Sizing and labelling

All four [sizes](#props) work; `size="tiny"` is the right pick for a dense toolbar or a table
footer. Segments hug their labels rather than sharing the width evenly; add `className="flex-1"`
to each item, and a width to the root, if you need them equal.

Always give the root an `aria-label` describing what is being switched or filtered — the segments
name the options, not the axis.

## Props

`ToggleGroup` forwards every prop to the underlying
[Radix Toggle Group](https://www.radix-ui.com/docs/primitives/components/toggle-group#api-reference),
and adds the following.

| Prop            | Type                                    | Default     | Description                                                                |
| --------------- | --------------------------------------- | ----------- | -------------------------------------------------------------------------- |
| `variant`       | `'default' \| 'outline' \| 'segmented'` | `'default'` | Styles the root and every item. Items inherit it through context.          |
| `size`          | `'tiny' \| 'sm' \| 'default' \| 'lg'`   | `'default'` | Item height and padding. Items inherit it through context.                 |
| `allowDeselect` | `boolean`                               | `true`      | Whether clicking the active item in a `type="single"` group clears it.     |
| `tone`          | `'outline' \| 'text' \| 'primary'`      | `'text'`    | Button-flavoured styling for a segmented group. Ignored by other variants. |

`variant` and `size` are the shadcn variant axes; `segmented` and `allowDeselect` are the Supabase
additions. `default` and `outline` are unchanged from shadcn.

### `allowDeselect`

Radix clears the selection when you click the already-active item of a `type="single"` group,
emitting `''` to `onValueChange`. That is right for a toolbar of optional toggles and wrong for a
segmented control, which always has exactly one thing selected.

Set `allowDeselect={false}` and the root swallows the empty value — `onValueChange` only fires
when the selection actually moves to another item.

```tsx
<ToggleGroup
  type="single"
  variant="segmented"
  size="tiny"
  value={view}
  onValueChange={setView}
  allowDeselect={false}
>
  <ToggleGroupItem value="data">Data</ToggleGroupItem>
  <ToggleGroupItem value="definition">Definition</ToggleGroupItem>
</ToggleGroup>
```

It defaults to `true`, so existing groups keep Radix's behavior. It has no effect on
`type="multiple"` groups, where an empty array is a legitimate value.

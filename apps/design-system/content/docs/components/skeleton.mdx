## Experimental: Dithered skeletons

The sections below are experimental implementations of a dithered loading texture that could replace `Skeleton` and `ShimmeringLoader`. They're for evaluation only. They share the same API (`className` plus `pixelSize`), use page coordinates so neighboring skeletons read as one surface, and respect reduced motion.

| Variant                             | Texture                                | Shine                                | Per-frame cost                            |
| ----------------------------------- | -------------------------------------- | ------------------------------------ | ----------------------------------------- |
| `DitheredSkeleton`                  | Procedural, drawn per cell on a canvas | Procedural, rippled edge             | Main-thread JavaScript, scales with area  |
| `DitheredSkeletonLite`              | Static, baked once into mask tiles     | Stepped `transform`, 3 dither levels | 3 compositor layers per instance          |
| `DitheredSkeletonGif`               | Drifting and pulsing, two GIF masks    | Soft `transform` sweep               | 1 compositor layer per instance           |
| `DitheredSkeletonGif shine={false}` | Drifting and pulsing, one GIF mask     | None                                 | None, the browser animates the GIF itself |

Compositor layers don't run JavaScript, but every extra animated layer makes each main-thread frame on the page more expensive (Chrome's layerization step), and costs more on devices that composite in software. That's why the GIF variant without shine is the cheapest option.

## Experimental: Canvas

`DitheredSkeleton` renders drifting noise through an ordered-dither pattern on a `<canvas>`, with a shine band whose edge ripples as it sweeps across. Every instance shares a single animation loop capped at 30 frames per second, and instances outside the viewport stop rendering. The per-cell work runs on the main thread, so cost grows with the skeleton's area and is highest on low-density screens.

### Fine grain

Set `pixelSize` below `1` to dither at device resolution, and add `grain` (`0`–`1`) for flickering film-like noise. Both multiply the per-frame cost.

## Experimental: Lite

`DitheredSkeletonLite` bakes the noise and dither once per cell size into small, seamless mask tiles shared by every instance. The shine is a stepped `transform` animation on a gradient layer, masked by three progressively denser dither tiles, so the browser runs it on the compositor.

The resting texture doesn't drift, the band edge is straight rather than rippled, and there's no `grain` option. Each instance has three animated layers, which matters on devices that composite in software.

## Experimental: GIF

`DitheredSkeletonGif` brings back the drifting texture without any per-frame JavaScript. The canvas version's noise is pre-rendered into two tiny looping GIFs (64×64 cells, 60 frames at 12.5 fps, about 21KB together), and used as luminance masks over the theme color:

- **Base:** the sparse resting texture, always visible. Its dither density breathes twice per loop, which gives the opacity pulse for free.
- **Highlight:** a denser version of the same drifting texture, revealed only under the shine.

The shine is a soft, asymmetric sweep, run as a `transform` animation on the compositor. Turn it off with `shine={false}`, and the only motion left is the GIF itself. The browser decodes each GIF once and animates it for every instance on the page, with no main-thread work and no extra layers.

The GIFs are generated by `packages/ui/src/components/DitheredSkeleton/scripts/generate-dither-gifs.mts`. Frames after the first only store the cells that changed, which roughly halves the file size. That's why the masks are read by luminance rather than alpha. With reduced motion, a still frame replaces each GIF.

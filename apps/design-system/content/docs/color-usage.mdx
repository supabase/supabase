The shorthand utility classes below simplify our full color palette by providing sensible, contrast-checked defaults. Use them whenever possible to ensure accessible text colors and balanced background fills.

## Brand green

Light mode uses two greens. Pick by job, not by habit:

| Use for                                        | Tokens                                                                             | Examples                                                              |
| ---------------------------------------------- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Text, primary fills, small selected indicators | `--primary`, `text-primary`, `border-primary`, `bg-primary`                        | Links, labels, radios, step dots, primary Button                      |
| Bright fills and focus                         | `brand-default`, `--ring`, `bg-brand-default`, `border-brand-default`, `ring-ring` | Focus rings, highlight rings, choice-card borders, bright status dots |

Use `--primary` when the green must meet WCAG AA as text, or when it is a solid primary fill. Use `brand-default` for focus rings and other bright chrome. Do not point `--ring` at `--primary`.

Dark mode barely differs between the two. The split matters most on light surfaces.

See also [Typography](../docs/typography) (`text-primary`) and [Accessibility](../docs/accessibility#focus-management) (shared focus ring).

## Text

Use accent text colors (e.g. text-destructive, text-warning) sparingly to avoid visual overload.

Use `text-primary` for readable branded text such as links, labels, and statuses. On light-theme
surfaces it meets the 4.5:1 WCAG AA requirement for normal text. For fills, borders, and focus
chrome, see [Brand green](#brand-green).

## Background

Use `bg-brand-default` when the canonical Supabase green is required as a fill. The same
`brand-default` suffix applies to borders and other non-text utilities, such as
`border-brand-default`. Prefer accessible `--primary` / `border-primary` for small selected
indicators (radios, step dots). Details in [Brand green](#brand-green).

### App backgrounds

We use backgrounds in 2 different ways. In the ./www and ./docs sites, we use a darker background, so we have an extra background color we can use

```jsx
/**
 * ./www background color
 * ./docs background color
 */
<body className="bg">{children}</body>

/**
 * ./studio background color
 */
<body className="bg-studio">{children}</body>
```

#### Data grid and frame space

Data grids use an alternative background color for empty space to add depth to the layout.
The background of the empty space is the same background as used in `./apps/docs` and `./apps/www` - although; the color has been mapped to `bg-alternative` so it works well across different themes.

<CodeFragment name="color-usage-surface-studio-frame" />

Dealing with large areas of empty space in data display should also be catered for. You can use the `bg-200` or `bg` class to fill the space.

### Overlays

We use the `./bg-overlay` background color for overlays.
This is not to be confused with `Dialogs`, they require to use the same app background color as the site.

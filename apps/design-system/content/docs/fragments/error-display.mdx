ErrorDisplay states what failed, explains it in plain language, shows the raw error, and offers ordered troubleshooting steps. It shares its icon, border, background, and text tokens with [`Admonition`](/docs/fragments/admonition), so the two read as one family.

It sizes itself to its **container**, not the viewport, so the same component works in a main content panel and in a 260px sidebar. Drag the width slider past 400px to watch `size="auto"` switch layouts.

## Layouts

`size="auto"` (the default) measures the container and switches at `COMPACT_LAYOUT_BREAKPOINT` (400px). Pass `size="compact"` or `size="full"` to force one.

|        | Full (≥ 400px)                               | Compact (< 400px)                       |
| ------ | -------------------------------------------- | --------------------------------------- |
| Header | Icon, title, "Try again" button              | Icon, title, icon-only retry            |
| Error  | Shown inline under the header                | Behind a "Details" toggle               |
| Steps  | Numbered timeline, title only until expanded | Stacked buttons, description as tooltip |

Rules that hold in both layouts:

- The error sits between the header and the steps, and carries the request ID, timestamp, and a copy button. With no `error`, nothing is rendered in its place.
- Steps are numbered only when there are two or more. A single step renders its action inline.
- A numbered step shows only its number and title until it expands. Expanding reveals the description and the action. The first step is expanded on mount; pass `defaultOpenStep` to pick another.
- Both layouts close with the same "Still stuck? Contact support" line, at the body's text size.
- Retry is never a numbered step. It belongs in the header.

## Usage

```tsx
import { ErrorDisplay } from 'ui-patterns/ErrorDisplay'
```

```tsx
<ErrorDisplay
  title="Failed to retrieve tables"
  description="The database connection timed out before the query finished."
  error={{ message: 'Connection terminated due to connection timeout', requestId: 'req_8f2a91c' }}
  onRetry={refetch}
  supportFormParams={{ projectRef }}
  steps={[
    {
      id: 'guide',
      title: 'Check the troubleshooting guide',
      description: 'Diagnose connection timeouts step by step.',
      action: { label: 'View guide', href: `${DOCS_URL}/guides/troubleshooting` },
    },
    {
      id: 'restart',
      title: 'Restart your project',
      description: 'Clears stale connections held by the pooler.',
      action: { label: 'Restart project', onClick: openRestartDialog },
    },
  ]}
/>
```

In Studio, wire [`ErrorMatcher`](https://github.com/supabase/supabase/tree/master/apps/studio/components/interfaces/ErrorHandling) on top so classified errors get their steps automatically.

`children` renders after the steps in both layouts. Use it for the dialogs your step actions open — they take no space until opened — or for anything else that has to sit inside the card. It doesn't get the compact treatment, so keep visible content short.

### Actions a button can't express

A step action is normally a `label` plus `onClick` or `href`. For a control a button can't express — a split dropdown, say — use `render`, which receives `{ block }` (`true` in the compact layout):

```tsx
{
  id: 'ai',
  title: 'Debug with AI',
  description: 'Ask the assistant to diagnose this error.',
  action: {
    label: 'Debug with AI',
    render: ({ block }) => <AiAssistantDropdown block={block} />,
  },
}
```

`label` is still required — it's what the compact layout announces. Don't reach for `render` for an ordinary button: it opts the step out of the built-in loading and external-link handling. For an action that opens a dialog, keep `onClick` and render the dialog through `children`.

## When to use each type

| Type          | Use when                                           | Role     |
| ------------- | -------------------------------------------------- | -------- |
| `info`        | A transient state the user should know about       | `status` |
| `warning`     | Nothing has failed yet, but it will without action | `status` |
| `destructive` | Something failed and the user can't continue       | `alert`  |

## Writing the steps

- **Order least to most disruptive.** Read a guide, then change a setting, then restart. The first step should be the cheapest thing that might work.
- **Retry is not a step.** It's one click with no consequences, so it lives in the header. Numbering it implies a sequence that doesn't exist.
- **Own the confirmation for anything that causes downtime.** ErrorDisplay fires `onClick` straight through — it has no inline confirmation. For restarts, failovers, and pausing a project, open a [`ConfirmationModal`](/docs/fragments/confirmation-modal) from the handler and state the consequence in active voice: "Restarting makes your database unavailable for about a minute."
- **Label the action, not the step.** The step title says what you're doing ("Restart your project"); the action label is the button ("Restart project"). In the compact layout only the action label is visible, so it has to stand alone.
- **One line per description.** It's revealed when the step expands in the full layout, and it's the button tooltip in the compact one — so it has to make sense without the title next to it.

## Props

| Prop                | Type                                   | Default             | Description                                                             |
| ------------------- | -------------------------------------- | ------------------- | ----------------------------------------------------------------------- |
| `title`             | `string`                               | —                   | What failed, phrased `Failed to <verb> <thing>`.                        |
| `type`              | `'info' \| 'warning' \| 'destructive'` | `'info'`            | Matches the Admonition variant of the same name.                        |
| `size`              | `'auto' \| 'compact' \| 'full'`        | `'auto'`            | `auto` switches on container width.                                     |
| `description`       | `string?`                              | —                   | Plain-language sentence shown under the title.                          |
| `error`             | `ErrorDisplayDetails?`                 | —                   | Raw error. Omit to drop it entirely.                                    |
| `onRetry`           | `() => void \| Promise<void>`          | —                   | Shows a retry button in the header. Pending promises show a spinner.    |
| `retryLabel`        | `string?`                              | `"Try again"`       | Retry button label, and its `aria-label` when icon-only.                |
| `steps`             | `ErrorDisplayStep[]?`                  | —                   | Troubleshooting steps, least to most disruptive.                        |
| `defaultOpenStep`   | `string?`                              | first step          | `id` of the step expanded on mount.                                     |
| `onStepOpenChange`  | `(stepId: string \| null) => void`     | —                   | Fired when a step expands or collapses. `null` when all are collapsed.  |
| `onContactSupport`  | `(details?) => void`                   | —                   | Fired with the error details when support is clicked.                   |
| `supportHref`       | `string?`                              | —                   | Overrides the generated support URL.                                    |
| `supportFormParams` | `SupportFormParams?`                   | —                   | Params for the support URL. Error message and request ID are merged in. |
| `supportLabel`      | `string?`                              | `"Contact support"` | Support link label.                                                     |
| `icon`              | `ReactNode?`                           | Admonition icon     | Overrides the header icon.                                              |
| `children`          | `ReactNode?`                           | —                   | Escape hatch for troubleshooting `steps` can't express.                 |
| `onRender`          | `() => void?`                          | —                   | Fired once on mount — use for telemetry.                                |
| `className`         | `string?`                              | —                   | Extra classes on the root element.                                      |

### ErrorDisplayStep

| Field         | Type                     | Description                                                   |
| ------------- | ------------------------ | ------------------------------------------------------------- |
| `id`          | `string`                 | Accordion value and React key.                                |
| `title`       | `string`                 | Step heading. Hidden in the compact layout.                   |
| `description` | `string?`                | One line. Shown on expand in full, button tooltip in compact. |
| `action`      | `ErrorDisplayStepAction` | The step's single action.                                     |

### ErrorDisplayStepAction

| Field     | Type                          | Description                                                                                     |
| --------- | ----------------------------- | ----------------------------------------------------------------------------------------------- |
| `label`   | `string`                      | Button label. Starts with a verb.                                                               |
| `onClick` | `() => void \| Promise<void>` | Pending promises show a spinner.                                                                |
| `href`    | `string?`                     | Renders a link. External links get an external-link icon. `onClick` still fires, for telemetry. |
| `icon`    | `ReactNode?`                  | Leading icon.                                                                                   |
| `render`  | `({ block }) => ReactNode`    | Custom control in place of the button. Escape hatch — see below.                                |

### ErrorDisplayDetails

| Field       | Type              | Description                                        |
| ----------- | ----------------- | -------------------------------------------------- |
| `message`   | `string`          | Raw error, rendered in monospace exactly as given. |
| `code`      | `string?`         | Machine-readable error code.                       |
| `requestId` | `string?`         | Sent to support as `sid`.                          |
| `timestamp` | `string \| Date?` | Dates are formatted as an ISO string.              |

### SupportFormParams

| Field        | Type      | Description                   |
| ------------ | --------- | ----------------------------- |
| `projectRef` | `string?` | Project reference slug        |
| `orgSlug`    | `string?` | Organization slug             |
| `category`   | `string?` | Pre-selected support category |
| `subject`    | `string?` | Pre-filled subject line       |
| `message`    | `string?` | Pre-filled message body       |
| `error`      | `string?` | Raw error string for context  |
| `sid`        | `string?` | Sentry event or request ID    |

## Accessibility

- The root is a live region: `role="alert"` for `destructive`, `role="status"` for `info` and `warning`, labelled by the title.
- Accordion triggers carry `aria-expanded` and `aria-controls`, and are keyboard operable.
- Icon-only buttons — compact retry, copy error details — carry `aria-label`s.

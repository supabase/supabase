ErrorDisplay states what failed, explains it in plain language, and offers the most useful recovery action. Less likely or more disruptive actions sit in an overflow menu. It shares its icon, border, background, and text tokens with [`Admonition`](/docs/fragments/admonition), so the two read as one family.

It sizes itself to its **container**, not the viewport, so the same component works in a main content panel and in a 260px sidebar. Drag the width slider past 400px to watch it adapt.

## Layouts

Action placement always follows Admonition's responsive composition: actions sit below the text in narrow containers and move to the right in wider containers. The frame keeps the same padding and typography at every width. Only sequential steps adapt at 400px.

|         | Full (≥ 400px)                      | Compact (< 400px)                   |
| ------- | ----------------------------------- | ----------------------------------- |
| Header  | Icon, title, description, raw error | Icon, title, description, raw error |
| Actions | Primary split button                | Primary split button                |
| Steps   | Numbered timeline                   | Stacked actions                     |

Rules that hold in both layouts:

- Raw technical details sit in one monochromatic monospace block with the title and description. Error code, request ID, and time follow the message in the same stream. Long content is initially capped and fades behind an inline "Show more" button.
- The first action is exposed. Remaining actions and contact support appear in its dropdown.
- When `onRetry` is supplied, "Try again" becomes the exposed action and every other action moves into the menu.
- Use `steps` only for instructions that must be completed in sequence. Two or more steps render as a numbered timeline.
- With no recovery actions, contact support renders as a direct button.
- Always provide `description`, `error`, or preferably both. A title alone does not give enough context to recover.

## Usage

```tsx
import { ErrorDisplay } from 'ui-patterns/ErrorDisplay'
```

```tsx
<ErrorDisplay
  title="Failed to retrieve tables"
  description="The database connection timed out before the query finished."
  error={{ message: 'Connection terminated due to connection timeout', requestId: 'req_8f2a91c' }}
  onRetry={refetch}
  supportFormParams={{ projectRef }}
  actions={[
    {
      id: 'guide',
      label: 'View guide',
      href: `${DOCS_URL}/guides/troubleshooting`,
    },
  ]}
/>
```

In Studio, wire [`ErrorMatcher`](https://github.com/supabase/supabase/tree/master/apps/studio/components/interfaces/ErrorHandling) on top so classified errors get their steps automatically.

`children` renders after the steps in both layouts. Use it for the dialogs your step actions open — they take no space until opened — or for anything else that has to sit inside the card. It doesn't get the compact treatment, so keep visible content short.

For genuinely sequential troubleshooting, use `steps`. A step can provide a custom `render` control when a button cannot express it, such as a split dropdown.

```tsx
action: { label: 'Debug with AI', render: ({ block }) => <AiAssistantDropdown block={block} /> }
```

## When to use each type

| Type          | Use when                                           | Role     |
| ------------- | -------------------------------------------------- | -------- |
| `info`        | A transient state the user should know about       | `status` |
| `warning`     | Nothing has failed yet, but it will without action | `status` |
| `destructive` | Something failed and the user can't continue       | `alert`  |

## Writing the actions

- **Order most to least recommended.** The first action is exposed. Put lower-confidence or more disruptive options in the menu.
- **Only supply retry when it is safe.** When supplied, it becomes the exposed action.
- **Do not model independent alternatives as steps.** Numbering implies that the user must complete actions in sequence.
- **Own the confirmation for anything that causes downtime.** ErrorDisplay fires `onClick` straight through — it has no inline confirmation. For restarts, failovers, and pausing a project, open a [`ConfirmationModal`](/docs/fragments/confirmation-modal) from the handler and state the consequence in active voice: "Restarting makes your database unavailable for about a minute."
- **Use standalone labels.** Action labels begin with verbs and make sense both as buttons and menu items.

## Props

| Prop                | Type                                   | Default             | Description                                                             |
| ------------------- | -------------------------------------- | ------------------- | ----------------------------------------------------------------------- |
| `title`             | `string`                               | —                   | What failed, phrased `Failed to <verb> <thing>`.                        |
| `type`              | `'info' \| 'warning' \| 'destructive'` | `'info'`            | Matches the Admonition variant of the same name.                        |
| `description`       | `string?`                              | —                   | Plain-language sentence shown under the title.                          |
| `error`             | `ErrorDisplayDetails?`                 | —                   | Raw error. Omit to drop it entirely.                                    |
| `onRetry`           | `() => void \| Promise<void>`          | —                   | Makes retry the primary action. Pending promises show a spinner.        |
| `retryLabel`        | `string?`                              | `"Try again"`       | Retry button label.                                                     |
| `actions`           | `ErrorDisplayAction[]?`                | —                   | Independent actions, most to least recommended.                         |
| `steps`             | `ErrorDisplayStep[]?`                  | —                   | Troubleshooting steps, least to most disruptive.                        |
| `defaultOpenStep`   | `string?`                              | first step          | `id` of the step expanded on mount.                                     |
| `onStepOpenChange`  | `(stepId: string \| null) => void`     | —                   | Fired when a step expands or collapses. `null` when all are collapsed.  |
| `onContactSupport`  | `(details?) => void`                   | —                   | Fired with the error details when support is clicked.                   |
| `supportHref`       | `string?`                              | —                   | Overrides the generated support URL.                                    |
| `supportFormParams` | `SupportFormParams?`                   | —                   | Params for the support URL. Error message and request ID are merged in. |
| `supportLabel`      | `string?`                              | `"Contact support"` | Support link label.                                                     |
| `icon`              | `ReactNode?`                           | Admonition icon     | Overrides the header icon.                                              |
| `showIcon`          | `boolean?`                             | `true`              | Shows or hides the header icon.                                         |
| `children`          | `ReactNode?`                           | —                   | Escape hatch for troubleshooting `steps` can't express.                 |
| `onRender`          | `() => void?`                          | —                   | Fired once on mount — use for telemetry.                                |
| `className`         | `string?`                              | —                   | Extra classes on the root element.                                      |

### Step and error shapes

```ts
type ErrorDisplayAction = {
  id: string
  label: string
  onClick?: () => void | Promise<void>
  href?: string
  icon?: ReactNode
}

type ErrorDisplayStep = {
  id: string
  title: string // hidden in the compact layout
  description?: string // shown on expand in full, button tooltip in compact
  action: {
    label: string // starts with a verb
    onClick?: () => void | Promise<void> // pending promises show a spinner
    href?: string // external links get an icon; onClick still fires, for telemetry
    icon?: ReactNode
    render?: (props: { block?: boolean }) => ReactNode // escape hatch, see above
  }
}

type ErrorDisplayDetails = {
  message: string // rendered in monospace exactly as given
  code?: string
  requestId?: string // sent to support as `sid`
  timestamp?: string | Date // Dates are formatted as an ISO string
}
```

### SupportFormParams

All optional: `projectRef`, `orgSlug`, `category`, `subject`, `message`, `error`, `sid`. `subject` defaults to the `title`, and `error`/`sid` are filled from `error` when you don't set them.

## Accessibility

- The root is a live region: `role="alert"` for `destructive`, `role="status"` for `info` and `warning`, labelled by the title.
- Accordion triggers carry `aria-expanded` and `aria-controls`, and are keyboard operable.
- Icon-only buttons — compact retry, copy error details — carry `aria-label`s.

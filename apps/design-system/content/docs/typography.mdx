Some reusable patterns work better as CSS variables, or “shorthands”, than as components. Typography is one of these cases, since its usage and context vary widely.

The shorthands below are composed of core [Tailwind utility classes](../docs/tailwind-classes). You can view the full list of shorthands in [`typography.css`](https://github.com/supabase/supabase/blob/master/packages/config/typography.css).

## Shorthands

| Value          | Usage                                               |
| -------------- | --------------------------------------------------- |
| `text-primary` | Accessible Supabase green for readable branded text |

`text-primary` meets WCAG AA for normal text on app surfaces: darkened in light mode,
bright in dark mode. Focus rings and selected controls derive their brighter fill from
the same primary hue. See [Primary and brand colors](../docs/color-usage#primary-and-brand-colors) for when
to use each green.

## Inline code

Inline `code` elements use shared styles by default in Studio, docs, www, and design-system.
The shared defaults live in [`inline-code.css`](https://github.com/supabase/supabase/blob/master/packages/config/inline-code.css).
No class is required. Inline code uses `font-size: calc(1em - 2px)` and inherits line height.
For example, code in 16px text is 14px; code in 14px text is 12px. This applies inside and outside `prose`.

A size class on the `code` element, such as `text-sm`, replaces the calculation. The 2px reduction
is not applied again. To change the surrounding size and keep the reduction, put the size class
on a parent instead:

```tsx
<span className="text-sm">
  <code>project_id</code>
</span>
```

Other local utility classes can adjust color, spacing, and wrapping.

Code inside `pre` elements and syntax-highlighting containers keeps its own styles.
For other custom code displays, add `data-code-style="plain"` to the `code` element
or a containing element to exclude its subtree from all default inline-code styles, including
background, border, padding, and sizing. Use this for displays with their own presentation,
such as command strips and syntax-colored header rows. A size override alone does not opt out
of the other inline-code styles.
